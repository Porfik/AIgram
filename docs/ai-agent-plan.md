# AIgram: ИИ-агент внутри клиента

Документ фиксирует решения дизайн-сессии от 2026-10-18 и уточнения перед
этапами. Этапы 0–4 и «Модели» завершены, этап 5 — нативный чат агента
(раздел 11.9).
Ссылки на код даны по символам и путям относительно `Telegram/SourceFiles/`.

## 1. Цель и инвариант

Агент выполняет по текстовому описанию любые действия, доступные пользователю
в клиенте, от его лица: читает и ищет переписку, пишет, пересылает, управляет
чатами, папками, профилем и настройками, а также работает в фоне по заданным
правилам.

Инвариант: каждое действие агента проходит через единый реестр инструментов
внутри клиента и через единый шлюз политики (область доступа режима,
исключённые чаты, уровни риска, подтверждения, рамки фоновых задач, бюджеты).
Ни один движок, включая внешний Claude Code, не обращается к Telegram в обход
реестра, и ни один инструмент не выполняется в обход шлюза.

Ограничение «лёгкости»: в AIgram не встраиваются Node, Python, Bun или другие
рантаймы. Всё, что поставляется с клиентом, написано на C++ поверх Qt и
существующих библиотек.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Аудитория | Открытый форк для всех желающих. Юридическая сторона (условия Anthropic и Telegram) сознательно не рассматривается |
| Синхронизация с upstream | Регулярные ребейзы. Код агента живёт в отдельной области, в существующих файлах только тонкие точки подключения |
| Движок | Свой лёгкий цикл агента на C++ |
| Провайдеры | Anthropic Messages API и OpenAI-совместимый Chat Completions (OpenAI, OpenRouter, DeepSeek, Gemini через совместимый эндпоинт, Ollama, LM Studio, vLLM). В настройках — профили моделей (раздел 11.7) |
| Первый адаптер | OpenAI-совместимый облачный |
| Подписка Claude | Необязательный второй движок: установленный пользователем бинарник `claude`, к которому AIgram подключается по протоколу Agent SDK |
| Режимы | Два режима: общий агент с доступом ко всему и агент чата, ограниченный одним чатом (раздел 3) |
| Общий агент в интерфейсе | С этапа 5 — локальный чат в самом списке чатов, закреплённый по умолчанию; открывается списком сессий, сессия — нативный чат с пузырями (раздел 11.9). На сервер не попадает |
| Агент чата в интерфейсе | Боковая панель в третьей колонке |
| Палитра команд | Слой поверх окна, быстрый вход в общего агента. Каждая команда сохраняется сессией общего агента |
| Автономность | Интерактивный режим и фоновые задачи |
| Права в диалоге | Уровни риска (раздел 6.1). Разрешение из карточки действует до конца поручения, для того же вида действия и тех же чатов |
| Права в фоне | Рамки задаются при создании задачи, всё вне рамок уходит в очередь подтверждений |
| Запуск фоновых задач | Структурный фильтр без модели, модель вызывается только при совпадении |
| Где работает фон | Пока запущен клиент, в том числе свёрнутый в трей |
| Уведомления фона | Настраиваются в задаче. По умолчанию тихое уведомление о каждом видимом другим действии. Очередь подтверждений и паузы по лимиту уведомляют всегда |
| Доступ к чатам | Все, кроме исключённых пользователем |
| Универсальная MTProto-команда | Только у общего агента, включена всегда, с подтверждениями и жёстким чёрным списком |
| Память | У каждого чата своя память, у общего агента своя. Общий агент может читать память чатов. Фоновые задачи память не видят |
| Общие инструкции | Поле в настройках. Пишет его только пользователь, видят все агенты и фоновые задачи |
| Несколько аккаунтов | Сессии, задачи, память и права — свои у каждого аккаунта. Провайдеры, ключи и общие инструкции — на всё приложение |
| Медиа | Фото, видео, голосовые, аудио и документы: модели, которая это умеет, или модели для медиа; голосовые ещё и через расшифровку Telegram (раздел 11.4) |
| Локальные файлы | Только явно переданные пользователем и папка агента |
| Расходы | Счётчик и лимиты, отдельная модель для фона |
| Пометка сообщений агента | Не делается. Если нужна подпись, пользователь просит её у агента сам |
| Отправка в чат агентом чата | Черновик в поле ввода этого чата |
| Отправка в чат общим агентом | Карточка с кнопками «Отправить», «В черновик», «Отклонить» |
| Хранение | Локально в зашифрованном tdata |

## 3. Режимы

### 3.1 Общий агент

- Закреплённая строка «✦ Агент» стоит над всеми закреплёнными чатами и
  показывает счётчик ожидающих подтверждений. Строка открывает экран агента в
  центральной колонке: ленту сессии и поле ввода. С этапа 5 это локальный
  чат в списке чатов: список сессий и нативный чат сессии (раздел 11.9).
- Список сессий. У каждой сессии видны затронутые чаты.
- Доступ ко всему, кроме исключённых чатов: любые чаты, навигация по
  настройкам, универсальная команда, фоновые задачи для любых чатов.
- Неявного контекста нет: какой чат открыт, общему агенту неважно, чаты
  называются в запросе.
- Палитра по горячей клавише — тот же общий агент поверх окна для разовых
  команд. Результат каждой команды сохраняется как сессия.
- Пункт «Передать агенту» в меню сообщения отправляет выделенные сообщения в
  новую сессию общего агента. Это замена пересылке, так как настоящим чатом
  «✦ Агент» не является.

### 3.2 Агент чата

- Кнопка ✦ в шапке чата открывает боковую панель.
- Сессия навсегда привязана к чату, в котором её начали. Панель показывает
  только сессии этого чата. При переключении чата панель переключается на
  сессии нового чата, а начатая работа доделывается в фоне.
- Доступно только содержимое этого чата:
  - история, поиск, участники;
  - сводка и перевод серверным ИИ Telegram;
  - черновик в поле ввода, правка и удаление своих сообщений;
  - реакции, закреп, звук, архив, папка;
  - администрирование этого чата;
  - фоновые задачи этого чата.
- Других чатов, навигации по настройкам и универсальной команды нет. Если
  просьба выходит за пределы чата, агент предлагает «Продолжить в общем
  агенте» и передаёт туда сессию как недоверенный контекст.
- В чат агент пишет только черновиком в поле ввода (`History::setLocalDraft`),
  с ответом на нужное сообщение. Если пользователь уже ушёл в другой чат,
  черновик остаётся в этом чате и виден в списке чатов как «Черновик: …».
- Изоляция встроена в сам режим: инструкция, подброшенная участником чата, не
  может ни прочитать другие чаты, ни написать в них.

## 4. Архитектура

```text
UI: экран «✦ Агент», панель чата, палитра, карточки, черновики
  |
Agent::Session        режим и область доступа, история, потоковый вывод,
  |                   память, учёт стоимости
  |  интерфейс Engine
  +-- NativeEngine                 свой цикл агента
  |     +-- OpenAiCompatAdapter    POST {base}/chat/completions, SSE
  |     +-- AnthropicAdapter       POST /v1/messages, SSE, кэш промптов
  +-- ClaudeCodeEngine (опция)     QProcess `claude -p`, stream-json,
                                   can_use_tool / mcp_message
  |  вызов инструмента
Agent::PolicyGate     область режима, исключения, уровни риска, taint,
  |                   рамки задач, бюджеты
Agent::ToolRegistry   ApiWrap, Data::Session, Core::DeepLinks::Router,
                      Settings::Builder::SearchRegistry, MTP-запросы
```

Область доступа (весь аккаунт или один чат) задаётся при создании
`Agent::Session` и проверяется в `PolicyGate`. Набор инструментов в контексте
модели зависит от режима, но фильтр в шлюзе — главная защита: даже вызов
инструмента, которого нет в контексте, проверяется по области.

### 4.1 Размещение кода

Новая область атласа `agent` с путями `SourceFiles/agent/` и своей картой
`SourceFiles/agent/AGENTS.md`. Запись в `SourceFiles/AGENTS.md` добавляется в
той же задаче, которая создаёт область.

- `agent/engine/` — интерфейс движка, свой цикл, адаптеры провайдеров, движок
  Claude Code.
- `agent/tools/` — реестр, группы инструментов, реализации.
- `agent/policy/` — области, уровни риска, исключения, taint, рамки, бюджеты.
- `agent/tasks/` — фоновые задачи, фильтры, планировщик, очередь подтверждений.
- `agent/storage/` — зашифрованное хранение сессий, памяти, задач, исключений.
- `agent/ui/` — экран общего агента, панель чата, палитра, карточки, раздел
  настроек.

Точки подключения в существующем коде (держать минимальными):

- **Строка «✦ Агент» в списке чатов** — механизм свёрнутых строк над списком
  (`CollapsedRow` в `dialogs/dialogs_inner_widget.h`).
- **Экран общего агента** — свой `Window::SectionWidget` и
  `Window::SectionMemento` (`window/section_widget.h`) в центральной колонке.
- **Панель агента чата** — `Info::Section::Type::Agent` и тег в `Info::Key`
  (`info/info_controller.h`). Прецедент секции без пира — теги
  `Downloads::Tag` и `Stories::Tag`.
- **Кнопка ✦** в шапке чата (`history/view/history_view_top_bar_widget*`).
- **Горячие клавиши** — новые значения `Shortcuts::Command`
  (`core/shortcuts.h`) для панели и палитры.
- **Меню чата и сообщения** — «Скрыть от агента» в `Filler`
  (`window/window_peer_menu.cpp`) и «Передать агенту» в меню сообщения
  (`history/view/history_view_context_menu.cpp`).
- **Владение состоянием.** Состояние агента на уровне аккаунта — компонент
  `Main::Session`. Провайдеры, ключи и общие инструкции — на уровне
  приложения.
- **Фоновые триггеры** подписываются на `Data::Session::newItemAdded()` без
  правок чужого кода.

### 4.2 Интерфейс движка

Движок принимает сообщение пользователя, умеет прерываться и отдаёт поток
событий: дельты текста, запрос вызова инструмента, результат, расход токенов,
ошибку и завершение хода. Внутреннее представление диалога — блоки `text`,
`image`, `tool_use` и `tool_result`. Каждый адаптер переводит его в формат
своего провайдера. UI и `Agent::Session` от выбора движка не зависят.

### 4.3 Свой цикл

- HTTP через `QNetworkAccessManager`. `core/sandbox.cpp` уже ставит SOCKS5/HTTP
  прокси клиента прокси всего приложения, поэтому запросы к провайдерам идут
  через него. MTProxy HTTPS не переносит, и в этом случае нужен отдельный
  SOCKS/HTTP-прокси.
- Возможности модели (вызов инструментов, зрение, размер контекста) берутся из
  ответа `/models` провайдера, если он их сообщает, иначе задаются в настройках.
- Контекстом управляет клиент, потому что серверные функции есть не у всех
  провайдеров:
  - оценка размера;
  - сжатие старых ходов в сводку той же или более дешёвой моделью;
  - обрезка больших результатов инструментов с продолжением по запросу.
- Для провайдера Anthropic включается кэш промптов. Чтобы кэш работал, порядок
  и текст инструментов и системного промпта в течение сессии не меняются.
- Каталог инструментов состоит из компактного ядра, которое всегда в контексте,
  и групп, подгружаемых метаинструментом `load_tools(group)`. Это нужно
  локальным моделям с контекстом 8–32 тысячи токенов. Подгруженные схемы
  дописываются в конец и не перестраивают уже отправленные.

### 4.4 Движок Claude Code (этап 4)

- AIgram находит `claude` в `PATH` или по пути из настроек и показывает вход
  из `claude auth status` (email и тариф). AIgram никогда не читает и не
  хранит учётные данные Claude: вход выполняет сам `claude auth login`,
  AIgram его только запускает (раздел 11.8).
- Запуск (проверено спайком на 2.1.304): `-p --input-format stream-json
  --output-format stream-json --verbose --include-partial-messages
  --tools "" --strict-mcp-config --mcp-config <сервер aigram типа sdk>
  --setting-sources "" --no-session-persistence --disable-slash-commands
  --permission-prompt-tool stdio --thinking-display summarized
  --model <модель>`, при уровне размышлений ещё `--effort`. Рабочая
  папка — пустая папка AIgram.
  Системный промпт передаётся в `initialize` (`systemPrompt`), а не файлом.
  `--bare` не подходит: в нём не читается вход по подписке.
- `initialize` объявляет сервер `aigram` в `sdkMcpServers` с настройками
  `disableAutoBackground` и `timeout` в 24 часа: вызов, который ждёт
  карточку, не уходит в фон и не обрывается (проверен вызов на 150 с, CLI
  присылает сердцебиение раз в 30 с). Сервер в `--mcp-config` помечен
  `alwaysLoad`, чтобы схемы не прятались за поиском инструментов. Ответ
  `initialize` содержит список моделей подписки.
- Инструменты — MCP-сервер внутри процесса: CLI шлёт JSON-RPC
  (`initialize`, `tools/list`, `tools/call`, `notifications/cancelled`) в
  управляющем запросе `mcp_message`, AIgram отвечает через `ToolRegistry`
  сессии, где работают `PolicyGate` и карточки. `can_use_tool` приходит
  перед каждым вызовом: AIgram разрешает только `mcp__aigram__*`, всё
  прочее запрещает. У каждого инструмента в `tools/list` стоит
  `_meta["anthropic/maxResultSizeChars"]`, иначе результаты больше ~50 КБ
  CLI сохраняет в файл.
- В результатах инструментов только текст и картинки: PDF и другие файлы
  из результата CLI сохраняет открытым файлом в `~/.claude/projects` даже
  при `--no-session-persistence`. Документы из инструментов модель
  подписки получает текстом (`agent_documents`), вложения пользователя —
  блоками сообщения, они на диск не пишутся.
- История передаётся «родными» кадрами stream-json: прошлые сообщения
  пользователя с `shouldQuery: false` (CLI отвечает `result` с `num_turns`
  0 и модель не спрашивает), ответы ассистента с `tool_use`, результаты
  инструментов. После каждого кадра пользователя хост ждёт его `result`,
  иначе CLI путает порядок и теряет результаты. Модель спрашивает только
  последний кадр. Чужие id вызовов (`call_0`) CLI принимает.
- Хост шлёт `interrupt` (CLI отменяет вызов через
  `notifications/cancelled` и заканчивает ход результатом
  `error_during_execution`) и `set_model`. Без входа ответ ассистента
  приходит с `error: "authentication_failed"`. `rate_limit_event` сообщает
  заполненность лимитов подписки за 5 часов и за неделю.
- Процесс запускается за ~1,3 с и в простое занимает ~240 МБ. В контекст
  CLI сам добавляет около 700 токенов: дату, окружение и email аккаунта
  Claude. Отключить это нельзя.
- Окружение процесса: прокси приложения в `HTTPS_PROXY`,
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, без переменных `CLAUDE*`
  родителя.
- Риск: протокол публично не документирован. Минимальная версия — 2.1.304,
  проверенная спайком; со старой версией AIgram просит обновить `claude`.

## 5. Инструменты

### 5.1 Ядро

Всегда в контексте общего агента:

- `get_context` — аккаунт, текущее время;
- `list_chats` — фильтры по папке, непрочитанным, типу;
- `read_history` — диапазон или окно вокруг сообщения, с пагинацией;
- `search_messages` — глобально или в чате, по отправителю и датам;
- `get_peer_info`;
- `send_message` — через карточку, с вариантом «в черновик»;
- `forward_messages`, `edit_message`, `delete_messages`;
- `react`, `mark_read`, `set_mute`, `set_archived`, `set_pinned`;
- `find_setting` и `open` — навигация, раздел 5.3;
- `memory` — своя память и чтение памяти чатов;
- `load_tools`.

У агента чата те же инструменты, но без параметра чата: целью всегда
является его чат. Списка чатов, глобального поиска, навигации и чтения чужой
памяти у него нет.

### 5.2 Группы

- **Администрирование чатов:** создание групп и каналов (только общий агент),
  приглашения, ссылки, участники, админы, ограничения.
- **Папки.**
- **Контакты и блокировки.**
- **Профиль:** имя, описание, фото, статус. Только общий агент.
- **Медиа** (этап 2a, раздел 11.4): просмотр фото и видео моделью,
  расшифровка голосовых через `Api::Transcribes` и прослушивание звука
  моделью, чтение документов, вложения в запросе, скачивание в папку
  агента, отправка переданных файлов.
- **Серверный ИИ Telegram:** `messages.summarizeText`,
  `messages.translateText`, `messages.composeMessageWithAI`.
- **Задачи:** создание, список, пауза и удаление фоновых задач. Агент чата
  управляет только задачами своего чата.
- **MTProto:** раздел 5.4.

### 5.3 Навигация

Только у общего агента. `Settings::Builder::SearchRegistry::collectAll()`
(`settings/settings_builder.h`) отдаёт по каждому пункту настроек заголовок,
ключевые слова, раздел, состояние галочки и deep link.
`Core::DeepLinks::Router` (`core/deep_links/`) открывает раздел и
подсвечивает конкретный элемент. Вместе они покрывают длинный хвост редких
действий без отдельного кода: агент находит место и открывает его, а последний
клик делает пользователь.

### 5.4 Универсальная MTProto-команда

- Доступна только общему агенту и только в интерактивных сессиях.
- Каталог методов генерируется при сборке из `mtproto/scheme/api.tl`. В
  контексте лежит только компактный список имён. Схему конкретного метода
  агент получает инструментом `describe_method`.
- Пиры передаются понятными ссылками (id, @username). `InputPeer` и
  `access_hash` собирает инструмент по данным `Data::Session`, модель их не
  видит. Исключённые чаты в параметрах отклоняются, а из ответов
  вычищаются.
- Методы-чтения (`*.get*`, `*.search*`, `*.check*`) выполняются без
  подтверждения. Всё остальное идёт через карточку с человеческим описанием
  действия.
- Чёрный список выполняется всегда, без исключений: удаление аккаунта,
  `auth.*`, пароль и его восстановление, сброс сессий, платежи, Stars, подарки
  и кошелёк.
- Ответ сериализуется из TL в JSON для модели и применяется к клиенту так же,
  как обычные ответы (например, `Updates` через `ApiWrap::applyUpdates`), чтобы
  интерфейс оставался согласованным.

### 5.5 Представление данных для модели

Сообщение передаётся компактно: id, дата, отправитель, текст с сущностями в
markdown, краткое описание медиа. Разбор из `export/data/export_data_types.h`
(`ParseMessage`, `ParseDialogsInfo`) переиспользуется там, где подходит.
Длинные результаты обрезаются, продолжение запрашивается пагинацией. Чтение
агентом не помечает сообщения прочитанными.

## 6. Политика

### 6.1 Уровни риска в диалоге

| Уровень | Действия | Поведение |
|---|---|---|
| Чтение и навигация | список чатов, история, поиск, профили, открытие экранов, методы-чтения MTProto | без подтверждения |
| Обратимые мелочи | без звука, архив, закреп, папки | без подтверждения, с записью в журнал и плашкой «Отменить» |
| Видимое другим или необратимое | отправка (у агента чата — только черновик), пересылка, реакции, редактирование, удаление, прочитано, вступление и выход, профиль, администрирование, прочие методы MTProto | карточка подтверждения |
| Запрещённое | чёрный список из раздела 5.4 | никогда |

В карточке есть галочка «разрешать такое до конца поручения». Разрешение
действует только до конца текущей просьбы пользователя, только для того же
вида действия и только для тех же целей (раздел 11.12).

### 6.2 Правило taint

Действует для общего агента. Если в поручении агент уже прочитал контент,
автор которого не пользователь (чужие сообщения, посты каналов, файлы, сессию,
перенесённую из агента чата), то отправка или пересылка в чат, который
пользователь не называл в запросе, всегда требует подтверждения. Разрешение до
конца поручения это правило не снимает. Недоверенный контент в результатах
инструментов размечается как данные, а не как инструкции. Агенту чата это
правило не нужно: писать за пределы своего чата он не может.

### 6.3 Исключённые чаты

Список исключённых чатов и папок ведётся отдельно для каждого аккаунта и
задаётся из меню чата. Исключённые чаты не видны ни одному инструменту, включая
результаты поиска и ответы универсальной команды. Писать в них запрещено.
Панель агента чата в исключённом чате недоступна.

### 6.4 Рамки фоновой задачи

Задача хранит, что ей разрешено: какие инструменты, в какие чаты, сколько
действий в час и какой бюджет. Всё, что выходит за рамки, попадает в очередь
подтверждений с уведомлением. Универсальная команда, память и навигация в фоне
недоступны. Рамки задачи, созданной из панели агента чата, ограничены этим
чатом.

### 6.5 Бюджеты

Расход токенов и примерная стоимость считаются по сессиям и задачам. У фона
есть дневной лимит и лимит на каждую задачу; при превышении задача ставится на
паузу с уведомлением. Массовые операции учитывают `FLOOD_WAIT` и ограничивают
темп, чтобы не получить ограничения аккаунта за спам.

## 7. Память и инструкции

- **Память чата.** У каждого чата своя память. Агент чата читает и дополняет
  её в интерактивных сессиях. Пользователь видит и правит её в панели.
- **Память общего агента** — своя. Общий агент дополняет её и при
  необходимости читает память любого чата. Писать в память чатов он не может.
- **Общие инструкции** — поле в настройках («отвечай кратко», «без эмодзи»).
  Пишет его только пользователь, видят все агенты и фоновые задачи.
- **Фоновые задачи** памяти не видят. Им доступны только собственная
  инструкция и общие инструкции, поэтому собеседник не может выудить
  через автоответчик заметки о себе.

## 8. Фоновые задачи

- **Создание.** Задачу создают из общего агента (для любых чатов) или из
  панели агента чата (только для этого чата). Агент предлагает структурное
  правило, а карточка показывает фильтр, промпт действия, рамки, модель,
  бюджет и режим уведомлений. Задача начинает работать только после одобрения.
- **Триггеры:**
  - входящее сообщение по фильтру (чаты, отправители, ключевые слова или
    регулярное выражение, тип медиа, упоминания, временное окно);
  - расписание;
  - разовый таймер.
- **Фильтр** проверяется на `Data::Session::newItemAdded()` без модели. Только
  совпадение запускает прогон агента с промптом задачи, а сработавшее сообщение
  передаётся как недоверенные данные.
- **Уведомления.** По умолчанию каждое видимое другим действие приходит тихим
  уведомлением; у задачи есть режим «только журнал». Очередь подтверждений и
  пауза по лимиту уведомляют всегда.
- **Списки.** Полный список задач живёт в общем агенте, задачи чата видны ещё
  и в его панели.
- **Время работы.** Задачи работают, пока запущен клиент. Пропущенные события
  по умолчанию не догоняются; у задачи есть опция обработать пропущенное при
  запуске.
- **Очередь.** Внутри одной задачи прогоны идут по одному, повторы
  отбрасываются. Элементы очереди подтверждений со временем устаревают.

## 9. Интерфейс

- С этапа 5 экран общего агента — список сессий и нативный чат сессии,
  история, задачи и память — в профиле агента (раздел 11.9).
- **Экран общего агента** открывается из строки «✦ Агент» в центральной
  колонке:
  - лента сессии и поле ввода;
  - список сессий с затронутыми чатами;
  - вкладки задач, памяти и очереди подтверждений;
  - журнал действий с отменой.
- **Панель агента чата** — секция Info в третьей колонке: сессии этого чата,
  его память и задачи. В узком окне панель открывается слоем поверх чата.
- **Палитра** — слой поверх всего главного окна, не отдельное окно ОС.
- **Ответ агента** рендерится как markdown средствами `iv/markdown`. Вызовы
  инструментов показываются сворачиваемыми строками, их можно раскрыть.
  Карточки подтверждений позволяют поправить текст перед выполнением.
- **Раздел настроек «Агент»:**
  - модели — профили с пунктом «Добавить модель» (раздел 11.7);
  - роли моделей — по умолчанию, фоновая, для медиа;
  - общие инструкции, лимиты, исключённые чаты;
  - путь к `claude`.

## 10. Хранение

- Данные аккаунта (сессии, память чатов и общего агента, задачи, исключения,
  статистика расходов) лежат в зашифрованном файле аккаунта
  (`Storage::details::EncryptedDescriptor`, `PrepareEncrypted` в
  `storage/details/storage_file_utilities.h`) и защищены локальным паролем,
  если он задан.
- Профили моделей, ключи и общие инструкции хранятся на уровне приложения в
  отдельном зашифрованном файле домена рядом с ключами кошелька
  (`Storage::Domain::readAgentSettings()`). Он шифруется локальным ключом и
  без локального пароля не расшифровывается, если пароль задан.
- Папка агента по умолчанию — `AIgram Agent` внутри папки загрузок Telegram.

### 11.1 Уточнения этапа 1

Этап 1 делится на три подэтапа, после каждого — вливание в `ai-agent` и
ручная проверка по чек-листу:

- **1a:** `Agent::Session` и `Agent::Manager`, `PolicyGate`, хранение
  сессий, управление контекстом, инструменты чтения своего чата, панель
  агента чата с кнопкой ✦.
- **1b:** инструменты действий, карточки, черновики, `load_tools` с группой
  «Папки», экран общего агента со строкой «✦ Агент», общие инструменты
  чтения и навигация, «Продолжить в общем агенте».
- **1c:** память, общие инструкции в промпте, исключённые чаты, счётчик
  расходов.

Решения:

- Сессии хранятся бессрочно, по файлу на сессию в зашифрованном хранилище
  аккаунта, удаляются только пользователем.
- Контекст: результаты инструментов обрезаются, а при заполнении ~70% окна
  модели старые ходы сжимаются в сводку той же моделью. Полная лента для
  пользователя сохраняется. Ошибка переполнения контекста вызывает сжатие и
  повтор хода.
- Название сессии придумывает модель отдельным коротким запросом после
  первого хода; пользователь может переименовать.
- Сообщение, отправленное во время хода, ждёт в очереди. «Стоп» прерывает
  ход и очищает очередь.
- Лента — свой виджет: пузыри пользователя, ответы через `iv/markdown`,
  сворачиваемые строки инструментов, карточки. В шапке «Новая сессия» и
  «История»; история открывает список сессий и вкладку памяти.
- Агент чата при старте видит только сводку чата и сам читает историю. В
  форуме сессия привязана ко всему форуму, а открытая тема передаётся
  подсказкой к сообщению.
- Черновик агента чата: при пустом поле ввода ставится сразу, при непустом —
  карточка «Заменить» / «Дописать» / «Отмена».
- Обратимые действия отменяются кнопкой «Отменить» у строки в ленте и
  «Отменить все» для хода. Общий журнал — в этапе 2.
- Taint: чат назван, если его @username, ссылка t.me или название есть в
  тексте поручения либо он вставлен @-автодополнением. Taint держится до
  конца сессии, а не одного поручения: прочитанный чужой контент остаётся в
  контексте модели.
- Память — список коротких фактов с id (`add` / `update` / `remove`), до 50
  записей, целиком в системном промпте при старте сессии.
- Расходы: токены всегда, деньги — если провайдер сообщает стоимость или в
  модели задана цена за миллион токенов. Лимиты — в этапе 2.
- Строка «✦ Агент» и кнопка ✦ видны, только когда настроен провайдер, и
  выключаются в настройках агента.
- Проверка: чистая логика в `td_agent` с тестами, клиент — сборкой и ручным
  чек-листом.

### 11.2 Исправление панели 1a и уточнения этапа 1b

Ручная проверка 1a показала, что лента панели разваливается. Причины
подтверждены снимками драйвера `ui-driver.sh` (вне репозитория, в
`~/.config/aigram/tools`):

- `object_ptr` не удаляет виджет с родителем, поэтому
  `FeedWidget::List::remove()` / `clear()` и `Composer::setQueued()`
  оставляют старые виджеты на экране;
- ребёнок, созданный под уже показанным родителем, скрыт без `show()`:
  новые сообщения, стриминг и пузыри очереди не видны;
- список ленты не следит за высотой элементов, раскрытая строка рисуется
  поверх следующих;
- `FlatLabel` со стилем `minWidth: 0` не переносит строки: обрезан пузырь,
  ошибка статуса и JSON уходят за края;
- в узком окне слой панели нулевой высоты;
- две шапки, лента открывается не внизу, всплывающий плейсхолдер
  `defaultInputField` в поле ввода, виден тег `<untrusted_data>`.

Исправление делается до работ 1b одним проходом (без воркеров), каждое
состояние проверяется снимками драйвера:

- лента на `Ui::VerticalLayout`, удаление виджетов явное;
- одна шапка: название сессии в шапке Info и кнопки «Новая сессия» и
  «История» в ней же (хук в одну строку в `Info::WrapWidget`);
- вызовы инструментов и размышления одного хода — одна сворачиваемая строка
  («Прочитал историю · 12 шагов»), ошибки отмечены, шаги раскрываются;
- перенос во всех метках, статус с отступами, слой с явной высотой,
  прокрутка вниз, поле ввода как в чате, `<untrusted_data>` срезается при
  показе.

Решения 1b:

- Пока висит карточка, ход ждёт решения: модель получает «выполнено»,
  «отклонено» или «исправлено на …» и продолжает тот же ход. Новое
  сообщение встаёт в очередь, «Стоп» отклоняет карточку и прерывает ход.
- Пакет: инструменты принимают список целей, на вызов одна карточка с
  галочками у целей и кнопкой «Выполнить (N)».
- «Отменить» у обратимых действий живёт до перезапуска клиента: прежнее
  состояние хранится в памяти, не в записи сессии.
- Удаление: только свои сообщения, галочка «Удалить у всех» включена там,
  где Telegram это позволяет. Чужие сообщения — в группе «Администрирование»
  этапа 3.
- Экран общего агента устроен как панель чата: та же шапка с «Новой
  сессией» и «Историей», история подменяет ленту списком сессий с аватарками
  затронутых чатов, лента по центру с ограничением ширины.
- `open` открывает сразу: настройки слоем с подсветкой пункта, чат в
  центре, экран агента уходит в стек, работа идёт в фоне, строка «✦ Агент»
  показывает «работает» и число ждущих карточек.
- «Продолжить в общем агенте»: агент чата кладёт в ленту карточку-кнопку,
  она открывает новую сессию общего агента с сессией чата как недоверенными
  данными (taint с первого хода) и запросом в поле ввода; отправляет
  пользователь.
- Группа «Папки»: список, создание, переименование, состав и порядок —
  обратимые с «Отменить»; удаление папки — карточка. Агент чата только
  добавляет свой чат в папку или убирает из неё.
- По умолчанию, без отдельного обсуждения: `set_pinned` закрепляет чат в
  списке (обратимо), закреп сообщения — видимое действие с карточкой и
  галочкой «уведомить», выключенной; карточка, ждавшая при выходе из
  клиента, после перезапуска показана как «не выполнено», ход прерван; в
  карточке правится только текст сообщения.
- Обратимые действия не прячутся в свёрнутой строке шагов: каждое идёт
  отдельной строкой под ней с «Отменить», при двух и более — «Отменить
  все».
- Строка «✦ Агент» есть только в списке «Все чаты»: в папках, архиве,
  форуме и поиске её нет.

### 11.3 Уточнения этапа 1c

Общие инструкции попадают в системный промпт с 1a: поле в настройках, а
промпт собирается заново на каждое сообщение пользователя. К 1c добавлено
удаление сессий.

Удаление сессий:

- В шапке панели чата и экрана общего агента есть меню ⋮ с пунктами
  «Переименовать» и «Удалить сессию» для открытой сессии. После удаления
  открывается пустая новая сессия.
- В списке сессий при наведении на строку справа появляется корзина.
  Удаление по правому клику остаётся.
- Удаление всегда подтверждается. Работающая сессия сначала
  останавливается.
- В настройках агента пункт «Удалить данные агента» удаляет у аккаунта все
  сессии, в том числе сессии чатов, которых уже нет, всю память и
  статистику расходов. Исключённые чаты остаются исключёнными.

Память:

- Факты с id (`m1`, `m2`, …), не больше 50 на владельца и 300 символов на
  факт, по одной строке. Владелец — чат или общий агент.
- Агент чата пишет в память своего чата, общий агент — в свою.
  Инструменты `memory_add`, `memory_update`, `memory_remove` обратимые:
  без карточки, строкой «Запомнил: …» в ленте с «Отменить».
  `read_chat_memory` есть только у общего агента: он читает память чата
  как недоверенные данные.
- Агент пишет сам, когда пользователь просит запомнить или явно сообщает
  устойчивое предпочтение или факт. Разовые детали поручений не пишет.
- Память целиком лежит в системном промпте и обновляется с каждым
  сообщением пользователя. Внутри хода промпт не меняется.
- «История» открывает две вкладки: «Сессии» и «Память». Во вкладке
  «Память» список фактов с «Изменить» и «Удалить», а также «Добавить факт»
  и «Очистить память». В панели чата видна память этого чата, на экране
  общего агента — память общего агента.

Исключённые чаты:

- Исключается чат или папка. Папка исключается вживую: чат скрыт, пока он
  в ней, в том числе чаты, добавленные позже, и чаты, попавшие в папку по
  её правилам. Исключённую папку агент не видит в списке папок и не может
  менять.
- Исключается только сам чат. Сообщения человека из скрытого личного чата
  в общих группах и сам этот человек в списке участников остаются видны
  как часть группы.
- Чат, названный по id, @username или ссылке, отвечает модели: «пользователь
  скрыл этот чат от агента». В списках и поиске скрытые чаты просто не
  появляются.
- Сессии и память исключённого чата не удаляются, а скрываются:
  работающая сессия останавливается, кнопка ✦ пропадает, открытая
  панель закрывается. Если чат снова показать агенту, всё вернётся.
- Пункты «Скрыть от агента» и «Показать агенту» есть в меню чата (в списке
  и в шапке) и в меню папки. В настройках агента есть список «Скрытые
  чаты»: в нём можно убрать чат или папку из исключений и добавить чаты.
  Пункты видны, только когда настроен провайдер.

Расходы:

- Стоимость берётся у провайдера, если он её сообщает (OpenRouter), иначе
  по трём необязательным ценам провайдера в долларах за миллион токенов:
  вход, выход, кэш. Без цен показываются только токены. Цена считается в
  момент ответа и дальше не пересчитывается.
- Учитываются все запросы, включая сжатие и названия сессий.
- В настройках раздел «Расходы» с итогами аккаунта за сегодня, за 30 дней
  и за всё время и кнопкой «Сбросить». Хранятся дневные суммы: они же
  нужны дневному лимиту этапа 2. Удаление сессий итоги не меняет.
- Переключатель «Показывать расходы в сессиях», по умолчанию выключен,
  общий для всего приложения. Когда он включён, в конце ленты видна строка
  расхода сессии с подробностями во всплывающей подсказке, а в списке
  сессий расход виден рядом с датой.

После проверки 1c строка «✦ Агент» и шапка экрана общего агента сделаны
максимально похожими на обычный чат: гладкая аватарка с градиентом, время
последней активности, последнее сообщение последней сессии, синее
«работает…» как «печатает…», бейдж ждущих карточек как непрочитанные, в
шапке — аватарка, «Агент» и строка статуса. Что показывать под названием
строки (последнее сообщение, название сессии или подсказку), выбирается в
настройках агента.

### 11.4 Этап 2: порядок и уточнения 2a

Этап 2 делится на два подэтапа, после каждого — вливание в `ai-agent` и
ручная проверка по чек-листу:

- **2a, медиа:** фото, видео, голосовые, аудио и документы из чатов,
  вложения в запросе, сохранение файлов в папку агента и отправка новых
  файлов. Сюда из этапа 3 переезжают группа «Медиа» и папка агента.
- **2b, фоновые задачи:** как в разделе 8, уточнения в разделе 11.5.
  Задачи сразу смогут пользоваться инструментами медиа, например
  расшифровать голосовое в автоответчике.

Интерфейс собирается из готовых элементов Telegram везде, где они
подходят: окно «Отправить файлы» (`SendFilesBox`), превью из
`ui/chat/attach/`, зона перетаскивания `DragArea`, кнопка скрепки,
просмотрщик медиа, «Показать в папке».

Чтение медиа:

- Агент читает фото, видео, кружки, GIF, стикеры, голосовые, аудио и
  документы из сообщений по id сообщения: общий агент — в любом видимом
  чате, агент чата — в своём.
- Картинки уходят модели уменьшенными. Видео и кружки — модели, которая
  видит видео; иначе модель получает обложку.
- Голосовые и аудио понимаются двумя способами, модель выбирает сама:
  расшифровка Telegram (`Api::Transcribes`) для голосовых и кружков и
  прослушивание — звук в WAV уходит модели, которая принимает аудио,
  кусками до 5 минут.
- Расшифровка с Premium выполняется без подтверждения. Без Premium —
  карточка «Потратить пробную расшифровку?» с остатком пробных. Без
  пробных или для слишком длинного голосового инструмент отвечает ошибкой
  и советует прослушивание. Расшифровка появляется и под голосовым в
  чате, как после кнопки расшифровки.
- Документы: текст и код клиент читает сам, постранично; из docx, xlsx,
  pptx, odt, ods и odp текст извлекается из zip с XML; PDF уходит модели
  файлом, если она принимает файлы, а у OpenRouter для остальных моделей
  включается бесплатный разбор `pdf-text`.
- Модель для медиа: в настройках агента можно выбрать одного из
  провайдеров списка. Если основная модель не умеет нужного (картинки,
  звук, видео, файлы), инструмент отдаёт медиа модели для медиа вместе с
  вопросом агента и возвращает её текстовый ответ. Её запросы учитываются
  в расходах. Без неё такие инструменты скрыты.
- Возможности модели (картинки, звук, видео, файлы) берутся из `/models`,
  если провайдер их сообщает, иначе отмечаются в настройках провайдера.
- Медиа видно модели до конца хода. В следующих ходах вместо него стоит
  строка «фото сообщения 123 чата X было показано раньше, вызови
  инструмент снова». Байты медиа в записи сессии не хранятся.
- Медиа из чужих сообщений и вложения — недоверенные данные (taint), как
  текст.

Вложения:

- Файлы и картинки прикладываются скрепкой, перетаскиванием и вставкой.
  Открывается стандартное окно «Отправить файлы» с подписью, его
  «Отправить» отправляет запрос агенту.
- Картинки вложений модель видит сразу, остальные файлы получает списком
  и открывает инструментами.
- Копия вложения хранится в зашифрованном хранилище аккаунта (до 50 МБ на
  файл, до 10 файлов на сообщение) и удаляется вместе с сессией и через
  «Удалить данные агента».

Сохранение и отправка:

- Папка агента — `AIgram Agent` в папке загрузок Telegram. Совпадающие
  имена получают номер, как обычные загрузки.
- До 20 МБ за вызов файлы скачиваются без вопроса, и для чтения, и для
  сохранения; больше — карточка «Скачать N файлов, X МБ?».
- Сохранение — обратимое действие: строка «Сохранил: …» с «Показать в
  папке» и «Отменить», которая удаляет сохранённые файлы.
- Отправлять агент может вложения своей сессии и файлы из папки агента.
  Общий агент — карточкой «Отправить» с превью файла, редактируемой
  подписью и галочками чатов. Агент чата открывает в своём чате
  стандартное окно «Отправить файлы» с файлом и подписью, отправляет
  пользователь.
- Инструменты чтения медиа есть всегда, сохранение и отправка — в группе
  `files` через `load_tools`.

Лента:

- Вложения в пузыре пользователя — миниатюры и плашки файлов, как в чате.
- В строке шагов — «Посмотрел фото», «Расшифровал голосовое 0:42» и т.п.;
  раскрытый шаг показывает миниатюру или текст расшифровки, клик по
  миниатюре открывает медиа в просмотрщике.

### 11.5 Уточнения этапа 2b

Кэш промптов делается внутри 2b (разбор расхода токенов от 2026-10-20):

- запросы к OpenRouter несут заголовок `x-session-id` с id сессии, у
  прогонов задачи — с id задачи; запросы к `api.openai.com` — поле
  `prompt_cache_key` с тем же id;
- непрочитанные и число участников уходят из системного промпта агента
  чата в подсказку `[Context]` сообщения, чтобы начало запроса не
  менялось всю сессию.

Метки `cache_control`, доля кэша в расходах, закрепление провайдера
OpenRouter, уровень размышлений и порог сжатия отложены. Выбор
провайдеров OpenRouter решён в разделе 11.7, метки `cache_control`, доля
кэша и уровень размышлений у профилей Anthropic — в разделе 11.8.

Создание и правка задач:

- Задачу создаёт агент инструментами группы `tasks` (через `load_tools`):
  общий агент — для любых чатов, агент чата — только для своего чата, и
  фильтр, и рамки. Карточка «Создать задачу» показывает триггер, фильтр,
  инструкцию (её можно поправить), рамки, модель, лимиты и режим
  уведомлений. Задача работает только после одобрения.
- Фильтр, расписание и рамки меняет агент по просьбе той же карточкой с
  изменениями. В интерфейсе задачи есть пауза и продолжение, удаление,
  режим уведомлений, лимиты и правка текста инструкции.

Триггеры:

- Новое сообщение по фильтру, расписание и разовый таймер.
- Фильтр проверяется без модели: чаты поимённо, по типу (личные, группы,
  каналы, боты) или по папке; отправители; ключевые слова или регулярное
  выражение; тип медиа; упоминания; временное окно.
- Срабатывают только чужие сообщения. Свои — только в «Избранном», если
  фильтр его называет. Сообщения, отправленные агентом, ничего не
  запускают. Скрытые от агента чаты не срабатывают никогда.
- Расписание: «каждые N минут или часов» (не чаще раза в 15 минут),
  «в такие-то времена по таким-то дням недели» и разовый таймер на дату и
  время. Время местное.

Прогон:

- Каждый прогон с чистого листа: системный промпт фона, инструкция
  задачи, общие инструкции и сработавшее сообщение как недоверенные
  данные (у расписания — время срабатывания). Памяти у фона нет, прошлое
  модель читает инструментами.
- Рамки: инструменты и чаты, заданные так же, как в фильтре, а у задачи
  с широким фильтром ещё «чат сработавшего сообщения». В чаты рамок
  задача пишет, реагирует и пересылает без вопросов.
- Чтение за рамками даёт ошибку. Действие за рамками (другой чат или
  инструмент) и карточка, которая спрашивает всегда (пробная расшифровка,
  большая загрузка), уходят в очередь подтверждений. Прогон ждёт решения,
  как карточка в диалоге. Через 24 часа карточка устаревает и считается
  отклонённой. Пока прогон ждёт, новые срабатывания задачи стоят в
  очереди.
- Фону недоступны универсальная команда, память, навигация, «Продолжить
  в общем агенте» и инструменты, открывающие окна. Только у фона есть
  инструмент `notify`: системное уведомление со звуком и коротким
  текстом, клик открывает прогон с полным текстом.
- Модель: в настройках «Фоновая модель» (один из провайдеров, по
  умолчанию основная), у каждой задачи можно выбрать свою.
- В задаче прогоны идут по одному, повторы одного сообщения отбрасываются,
  ждущих срабатываний не больше 20 (новые сверх этого отбрасываются с
  пометкой). Одновременно идут не больше трёх прогонов аккаунта, в
  прогоне не больше 20 запросов к модели.
- Пропущенное, пока клиент был закрыт, по умолчанию не догоняется. С
  опцией задачи «обработать пропущенное» при запуске идёт один прогон по
  пропущенным сообщениям или одно пропущенное срабатывание расписания.

Лимиты и уведомления:

- Лимиты только у фона: дневной лимит всего фона в настройках (по
  умолчанию $1), у задачи — дневной лимит ($0,25) и действий в час (30).
  В деньгах, когда цена известна, иначе в токенах (1 млн и 250 тыс.).
  При превышении задача встаёт на паузу с уведомлением; дневная пауза
  снимается на следующий день, часовая — когда освободится час.
- Уведомления — системные уведомления клиента от имени задачи: аватарка
  чата, название задачи, что сделано. По умолчанию каждое видимое другим
  действие — тихое уведомление, у задачи есть режим «только журнал».
  Очередь подтверждений, паузы по лимиту и `notify` уведомляют всегда, со
  звуком. Клик открывает прогон или карточку.

Интерфейс и хранение:

- «История» получает три вкладки: «Сессии», «Задачи», «Память». В общем
  агенте — все задачи аккаунта, в панели — задачи этого чата. Задача
  открывается подробностями и списком прогонов, прогон — лентой только
  для чтения, в которой действия можно отменить до перезапуска.
- Ждущие карточки фона считает бейдж строки «✦ Агент». Над лентой
  общего агента (и панели — для задач этого чата) плашка «Ждут решения:
  N» открывает список карточек с названием задачи и сработавшим
  сообщением.
- Задачи и прогоны лежат в зашифрованном хранилище аккаунта, у задачи —
  последние 50 прогонов. «Удалить данные агента» удаляет и задачи.
- Общий журнал всех действий агента отложен.

### 11.6 Этап 3: порядок и решения

Этап 3 делится на три подэтапа, после каждого — вливание в `ai-agent` и
ручная проверка по чек-листу:

- **3a, группы инструментов:** администрирование, контакты и блокировки,
  профиль, серверный ИИ Telegram.
- **3b, входы:** палитра и «Передать агенту».
- **3c:** универсальная MTProto-команда.

Группы 3a подгружаются `load_tools`: `admin`, `contacts`, `profile` и
`telegram_ai`. Все четыре доступны фоновым задачам, профиль тоже:
действия вне рамок задачи, как и раньше, ждут решения в очереди. Чтение
идёт без подтверждения, изменения, видимые другим, — карточкой с
галочками у целей и «разрешать до конца поручения».

Администрирование:

- Участники: добавить, исключить, забанить, ограничить, снять
  ограничения; удалить чужие сообщения и все сообщения участника.
- Админы: назначить и снять, права, должность.
- Пригласительные ссылки: список, создание, изменение, отзыв; заявки на
  вступление: список, одобрение, отклонение.
- Настройки чата: название, описание, фото, права по умолчанию,
  медленный режим. Создание групп и каналов — только у общего агента.
  Вступление по ссылке или @username и выход из чата.
- Агент чата администрирует только свой чат. Если у пользователя нет
  нужного права, инструмент отвечает ошибкой с названием права.

Контакты и блокировки:

- Список контактов и заблокированных — чтение.
- Переименование контакта видно только пользователю: обратимое
  действие, строка с «Отменить».
- Добавление, удаление контакта, блокировка и разблокировка — карточка:
  собеседник это замечает.
- Агент чата может всё это только в личном чате и только для
  собеседника; в группах и каналах этих инструментов у него нет.

Профиль — только общий агент, каждое изменение карточкой со старым и
новым значением:

- имя, фамилия и «О себе»;
- фото профиля из вложения или файла папки агента, удаление текущего
  фото;
- эмодзи-статус со сроком; без Premium инструмент отвечает ошибкой.
- Юзернейм, день рождения и личный канал агент не меняет: для них есть
  навигация по настройкам.

Серверный ИИ Telegram:

- Сводка сообщения (`messages.summarizeText`) появляется и в чате, как
  после кнопки «Сводка», так же, как расшифровка в 2a.
- Перевод сообщений или текста (`messages.translateText`) и правка
  текста (`messages.composeMessageWithAI`: вычитка, эмодзи, тон,
  перевод) возвращаются только агенту, в чате ничего не меняется.
- Результаты по чужим сообщениям — недоверенные данные. Ограничения
  Telegram (лимит сводок без Premium и т. п.) приходят модели ошибкой.
- Агенту чата доступны сводка и перевод сообщений своего чата и правка
  текста.

Палитра (3b):

- Ctrl+Shift+Space (переназначается, как остальные горячие клавиши)
  открывает слой поверх главного окна: поле ввода сверху, под ним
  мини-лента с шагами, ответом и карточками. Esc закрывает палитру,
  работа продолжается в фоне.
- Первая команда создаёт сессию общего агента, следующие, пока палитра
  открыта, продолжают её. Новое открытие палитры — новая сессия, есть
  кнопка «Новая».
- «Открыть в агенте» переносит сессию на экран общего агента. Сессии
  палитры — обычные сессии общего агента и видны в его истории.
- Палитра знает открытый чат: к сообщению добавляется подсказка
  `[Context]` с этим чатом, и он считается названным для правила taint.

«Передать агенту» (3b):

- Пункт в меню сообщения и на панели выделенных сообщений открывает
  палитру. Выбранные сообщения висят над полем ввода плашкой «N
  сообщений из чата X», как при пересылке; пользователь дописывает
  просьбу.
- Сообщения уходят модели как недоверенные данные в том же виде, что
  у `read_history` (с id чата и сообщений, медиа открываются
  инструментами медиа). Сессия помечена taint с первого хода, чат
  сообщений считается названным.

Универсальная MTProto-команда (3c), уточнения к разделу 5.4:

- Группа `mtproto` через `load_tools`, только у общего агента в
  интерактивных сессиях: `find_methods` (поиск по именам и параметрам,
  без запроса — список пространств имён), `describe_method` (схема
  метода и нужных типов) и `call_method`. Список имён в контексте не
  лежит.
- Методы-чтения выполняются без подтверждения, кроме чтений с побочным
  действием (ответ бота на кнопку, инлайн-запрос боту, рост счётчика
  просмотров, поиск людей рядом): они идут карточкой.
- Карточка: строка описания от модели (помечена как слова модели), имя
  метода, чаты по названиям; полные параметры в JSON раскрываются.
  «Разрешать до конца поручения» действует для того же метода и тех же
  чатов. Для правила taint все вызовы считаются исходящими.
- Чёрный список, кроме перечисленного в 5.4: срок самоудаления
  аккаунта, смена номера и почты, Telegram Passport, передача владения
  чатом или ботом, вход на сайты через Telegram, веб-приложения ботов,
  выгрузка данных (takeout).

Уточнения 3c (2026-10-20):

- Ссылка в параметрах на скрытый чат отклоняется везде, в том числе на
  человека, чей личный чат скрыт (`InputUser` тоже): `call_method` не
  показывает того, что скрывает `get_peer_info`. В ответах люди
  остаются, как и раньше.
- Методы, для которых есть свой инструмент с удобной карточкой
  (отправка, пересылка, правка, удаление, реакция, закреп, прочитано,
  звук, архив, закреп чата, папки, профиль, контакты и блокировка,
  администрирование из 3a), `call_method` не выполняет и называет нужный
  инструмент.
- Файлы и медиа в 3c не поддерживаются: значения с `access_hash` или
  `file_reference`, а также загружаемые файлы (`InputFile`) модель
  передать не может, об этом говорят ошибка и описание метода. Файлы
  идут через `send_files`, `set_chat_photo` и `set_profile_photo`.
- Для методов, которые что-то меняют, строка описания для карточки
  обязательна. Чаты передаются id из других инструментов, @username или
  id из ответов MTProto (`user_id`, `chat_id`, `channel_id`; при
  совпадении — `channel:<id>` и т. п.).

Проверка 3a (2026-10-20): провайдер InferenceNet, на которого OpenRouter
часто направляет GLM 5.3 Flash, при полном наборе инструментов теряет
аргументы вызовов (вызов приходит только с `chat`). Без него те же
запросы приходят полными. Настройка исключения провайдеров OpenRouter
по решению пользователя отложена вместе с закреплением провайдера; её
заменили профили моделей (раздел 11.7).

### 11.7 Этап «Модели»: профили моделей

Отдельный этап между 3 и 4 (решено 2026-10-20). Список провайдеров
становится списком профилей моделей: профиль — это сервис, ключ, модель и
название, которое видит пользователь. Пункт «Anthropic» переезжает в этап 4
целиком: у пользователя подписка Claude без ключа API, а подписка работает
только через `claude`.

Добавление модели:

- В настройках агента — список «Модели» и пункт «Добавить модель». Он
  открывает выбор: «OpenRouter» и «Другой провайдер». «Anthropic»
  появляется в этапе 4, другие интеграции — позже; до тех пор их в меню
  нет.
- OpenRouter: ключ, затем модель из списка с поиском, затем название
  (подставлено имя модели) и галочка «Модель по умолчанию». Ключ
  проверяется сразу после ввода.
- Ключ один на сервис: если профиль OpenRouter уже есть, шаг ключа
  пропускается. Смена ключа в любом профиле OpenRouter меняет его у всех.
- Список моделей OpenRouter берётся из публичного `/models`. В нём только
  модели с вызовом инструментов, поиск идёт по названию и id. В строке
  видны id, окно контекста и цены за миллион токенов. Окно, возможности
  (картинки, звук, видео, файлы) и цены копируются в профиль при выборе.
- «Другой провайдер» — прежняя форма: название, адрес, ключ, модель,
  возможности, цены.
- Окно профиля OpenRouter: название, модель (тот же список), ключ,
  «Провайдеры OpenRouter», «Проверить подключение» и «Удалить».
  «Провайдеры OpenRouter» по умолчанию «Автоматически». Там список
  провайдеров этой модели из `/models/<id>/endpoints` с галочками, снятые
  уходят в запросы как `provider.ignore`. Чтобы закрепить провайдера,
  оставляют отмеченным одного. Так обходится InferenceNet, который
  теряет аргументы вызовов GLM (раздел 11.6).

Роли:

- В настройках остаются «Модель по умолчанию» (с неё начинается новая
  сессия), «Фоновая модель» и «Модель для медиа», каждая — выбор из
  профилей. У задачи по-прежнему свой выбор модели.
- Сжатие контекста и название сессии делает модель сессии.

Смена модели в чатах:

- Над полем ввода в панели чата, на экране общего агента и в палитре
  стоит кнопка с названием модели сессии. Клик открывает список профилей
  с галочкой у текущего и пунктом «Добавить модель…».
- Выбор запоминается сессией. Новая сессия начинает с модели по
  умолчанию, сессия после «Продолжить в общем агенте» тоже. Смена
  посреди сессии действует со следующего сообщения, ход, который уже
  идёт, доделывает прежняя модель.
- Если профиль сессии удалён, сессия работает на модели по умолчанию.

Перенос сохранённых настроек:

- Каждый сохранённый провайдер становится профилем «Другой провайдер» со
  всеми полями, без распознавания OpenRouter. Активный провайдер
  становится моделью по умолчанию. Id сохраняются, поэтому фоновая
  модель, модель для медиа и модели задач остаются выбранными.

По умолчанию, без отдельного обсуждения:

- «Проверить подключение» переезжает со страницы в окно профиля;
- удаление профиля подтверждается;
- окно контекста и возможности модели сессии клиент, как и раньше,
  уточняет через `/models`, теперь для модели каждой сессии;
- поведение по адресу OpenRouter (стоимость из ответа, `x-session-id`,
  разбор PDF) остаётся у любого профиля с этим адресом, в том числе у
  перенесённых.

### 11.8 Этап 4: Anthropic и подписка Claude

Решено 2026-10-20 после спайка протокола `claude` (раздел 4.4) и обзора
похожих интеграций (Hermes, AIbroker, senpi, 9router, Zed). Правила
Anthropic разрешают пользователю входить своей подпиской в
немодифицированный `claude`, который запускает другая программа, и
запрещают сторонним программам свой вход Claude.ai и работу с токенами.
Поэтому AIgram запускает `claude` и его собственный вход, но учётных данных
не касается.

Добавление модели:

- В «Добавить модель» появляется «Anthropic» с двумя способами: «Подписка
  Claude» и «Ключ API».
- Подписка — мастер в окне. Сначала AIgram ищет `claude` (`PATH` или путь
  из настроек). Нет — инструкция установки с командой, «Указать путь» и
  «Проверить снова»; версия старше проверенной — просьба обновить. Нет
  входа — кнопка «Войти в Claude»: AIgram запускает `claude auth login
  --claudeai`, тот сам открывает браузер и принимает ответ на своём
  локальном адресе. Окно ждёт завершения и показывает «Вход: email, тариф»
  из `claude auth status`. Если браузер не открылся, CLI просит вставить
  код: его AIgram не принимает и советует выполнить `claude auth login` в
  терминале.
- Затем модель из списка, который `claude` отдаёт в ответе на
  `initialize`: сверху «последние» Opus, Fable, Sonnet и Haiku
  (псевдонимы, сами переходят на новую версию), ниже конкретные версии.
  Потом название (подставлено, например «Claude Opus 5.5») и «Модель по
  умолчанию».
- Профиль на модель, как у OpenRouter: «Claude Opus 5.5», «Claude Haiku
  5.5». Вход один на все профили подписки, следующий профиль шаг входа
  пропускает. В списке моделей подпись «Подписка Claude · opus», в кнопке
  над полем ввода — название профиля.
- Ключ API: ключ проверяется запросом `/v1/models`, список моделей берётся
  оттуда (окно, возможности), цены — из встроенной таблицы, их можно
  поправить. Ключ один на сервис, как у OpenRouter.
- У профилей Anthropic есть «Размышления»: «Как у модели», низкий,
  средний, высокий, очень высокий и максимум — только уровни, которые
  модель умеет. Подписке уровень уходит флагом `--effort`, ключу —
  `output_config.effort`. У OpenRouter и других провайдеров уровня пока
  нет.

Работа подписки:

- Тёплый процесс на сессию: живёт, пока с сессией работают, закрывается
  после 10 минут простоя или при смене модели. Тёплых процессов не больше
  трёх, лишний — самый давний. Новый процесс получает историю родными
  кадрами (раздел 4.4). Прогон фоновой задачи — свой процесс на прогон.
- Историю, сжатие и названия ведёт сессия AIgram, как у своего цикла. Окно
  контекста профиля подписки — 200 тысяч токенов: дальше подписка требует
  оплаты длинного контекста.
- Модель подписки видит картинки; аудио и видео идут через модель для
  медиа, документы из инструментов — текстом (раздел 4.4).
- Когда `claude` пропал или вход потерян, ход заканчивается понятной
  ошибкой в ленте с кнопкой «Настройки модели».
- Процессы AIgram запускают `claude` без телеметрии, отчётов об ошибках и
  автообновления (`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`). На
  `claude` в терминале это не влияет.

Расходы и кэш:

- Подписка: токены считаются как обычно, денег нет. Окно профиля и
  «Расходы» в настройках показывают заполненность лимитов подписки за 5
  часов и за неделю со временем сброса (`rate_limit_event`). Лимиты фона у
  задач на подписке — в токенах.
- Ключ API: кэш промптов метками `cache_control`. Стоимость — по ценам
  профиля: чтение кэша по своей цене из таблицы, запись в кэш — 1,25 цены
  ввода.
- Отложенное из 11.5 входит в этап: метки `cache_control` для моделей
  `anthropic/*` через OpenRouter (та же разметка, что у
  `AnthropicAdapter`) и доля кэша в расходах — «кэш N%» в строке расходов
  сессии и в суммах настроек, запись в кэш учитывается отдельно.

Общий разбор потока: события Messages API (`message_start`,
`content_block_*`, `message_delta`, `message_stop`, `error`) разбирает один
модуль. У `AnthropicAdapter` они приходят по SSE, у подписки — внутри
`stream_event` CLI.

По умолчанию, без отдельного обсуждения:

- запросы по ключу к моделям с защитными классификаторами идут с
  `fallbacks: "default"`: при отказе классификатора API повторяет запрос
  на запасной модели;
- размышления Claude показываются в ленте кратким пересказом
  (`display: "summarized"`), а не пустыми блоками;
- путь к `claude` задаётся в окне профиля подписки и хранится на уровне
  приложения, один на все профили.

### 11.9 Этап 5: нативный чат агента

Решено 2026-10-21. Чат общего агента выглядит и ведёт себя как чат с
пользователем или ИИ-ботом Telegram и собирается из виджетов чатов
Telegram, а не из своих. Основа — локальный собеседник: `UserData` бота с
id из диапазона фальшивых пользователей (`Data::FakePeerIdForJustName()`),
его `History` и локальные сообщения. На сервер он не попадает: каждая
точка, где клиент отправил бы о нём запрос, пропускает его.

Список чатов:

- Агент — локальный чат в самом списке «Все чаты». Строку рисует Telegram:
  аватар, имя, превью последнего сообщения (по настройке «Под именем»:
  последнее сообщение, название сессии или подсказка), дата, галочка,
  «печатает…» во время работы, «Черновик:», счётчик ожидающих карточек.
- По умолчанию он закреплён обычным механизмом Telegram: булавка,
  перетаскивание среди закреплённых, «Открепить» ставит его по дате
  последнего сообщения. Место среди закреплённых хранится локально; список
  закреплённых с сервера его не выбрасывает, а порядок, который уходит на
  сервер, его не содержит. В лимит закреплённых он не входит.
- Поиск по чатам находит его по имени. В папках его нет. Переключатель
  «Показывать агента в чатах» убирает его из списка.
- Меню строки — своё: закрепить или открепить, «Новая сессия», «Профиль»,
  «Настройки агента». Действий сервера (звук, архив, удаление, блокировка,
  жалоба) нет.
- Открытие чата агента из любого места (строка, поиск, отдельное окно)
  показывает список сессий.

Список сессий:

- Открытие показывает список сессий в центральной колонке, как список тем
  форума. Шапка — как у чата: аватар, имя, статус («печатает…» или «ждёт
  вашего решения», когда работает какая-то сессия), меню «⋮».
- Сверху строка «＋ Новая сессия», ниже сессии от новых к старым: название,
  последнее сообщение, дата, «печатает…» во время работы, счётчик карточек.
  Поля ввода на экране списка нет.
- Клик открывает сессию как чат, «назад» возвращает к списку. Контекстное
  меню сессии: «Переименовать» и «Удалить».

Чат сессии:

- Лента — `HistoryView::ListWidget` над локальными сообщениями сессии, с
  обоями и стилем чатов, плашками дат и временем у сообщений. Шапка — как у
  темы форума: название сессии, под ним имя агента, «печатает…» или «ждёт
  вашего решения»; клик открывает профиль агента.
- Сообщения пользователя — исходящие. Вложения — настоящие фото и файлы в
  сообщении. Сообщение, отправленное во время работы, видно сразу с часами
  отправки, пока агент его не возьмёт.
- Ответ агента — входящее «богатое сообщение» (`Iv::RichPage`, как у
  ИИ-ботов Telegram): markdown из `Iv::Editor::BlocksFromMarkdown()`,
  таблицы, код. Шаги инструментов хода — сворачиваемый блок «Details» в
  начале пузыря («Прочитал историю · 12 шагов», ошибки отмечены, у шага
  раскрываются аргументы и результат), размышления — блок «Thinking».
  Пузырь растёт по мере ответа; во время работы в шапке «печатает…», а
  кнопка отправки становится «Стоп».
- Карточка подтверждения — отдельное входящее сообщение: что будет сделано
  и инлайн-кнопки по виду карточки («Отправить (N)», «В черновик»,
  «Отклонить»; «Подтвердить (N)»; «Продолжить в общем агенте»). «Изменить…»
  открывает окно с прежней карточкой (текст, галочки чатов, параметры).
  Решённая карточка теряет кнопки и получает строку итога.
- Отменяемые действия хода — кнопки «Отменить» (по одной на действие или
  «Отменить всё») под ответом; после отмены — «Отменено».
- Ошибка хода — входящее сообщение с текстом ошибки и кнопками «Повторить»
  и «Настройки модели». Сжатие контекста — служебная плашка.

Поле ввода:

- Родное `HistoryView::ComposeControls`: эмодзи, вложения (окно
  `SendFilesBox`, вставка, перетаскивание), без стикеров, голоса, отложенной
  отправки и встроенных ботов.
- Модель сессии — родная синяя кнопка меню бота слева от поля с названием
  профиля; клик открывает список профилей с галочкой и «Добавить модель…».

Профиль агента:

- Клик по шапке чата агента открывает профиль в третьей колонке (в узком
  окне — слоем), как профиль пользователя: большой аватар, имя, статус. В
  шапке профиля «Изменить» — окно с фото (выбор файла, обрезка, сброс к ✦)
  и именем, как у контакта.
- Ниже: «Модель по умолчанию», «Задачи», «Память», «Журнал действий» и
  «Настройки агента». Задачи, память и журнал открываются внутри профиля,

- Имя и фото хранятся на всё приложение рядом с профилями моделей. Они же
  есть в Настройки → ИИ-агент, блок «Профиль агента». По умолчанию имя
  «Агент» и фиолетовый аватар с ✦.

Панель и палитра:

- Панель агента чата и палитра используют тот же нативный вид сессии.
  Панель — те же пузыри и поле ввода в третьей колонке, её история (сессии,
  задачи, память этого чата) остаётся вкладками. Палитра — компактно, поле
  ввода сверху, лента под ним.
- Старая лента (`FeedWidget`, самодельные пузыри и шаги) удаляется, виджеты
  карточек остаются только для окна «Изменить…».

Остатки прошлых этапов, вошедшие в этап:

- «Журнал действий» в профиле (раздел 9): все действия агента от новых к
  старым — что сделано, в каком чате, когда, из какой сессии или задачи, с
  «Отменить», пока действие можно отменить. Клик открывает сессию.
- Переданные сообщения (хвост 3b) видны в исходящем сообщении как родные
  пересланные. Пересылка в чат агента через обычное окно пересылки
  работает как «Передать агенту».
- Без отдельного обсуждения: спайк, почему подписка Claude отдаёт только
  псевдонимы моделей; проверка закрытия тёплого процесса после 10 минут
  простоя.
- Итог спайка (2026-10-21, `claude` 2.1.304): полный список моделей с
  версиями (Haiku 4.5, Opus 4.6–4.8 и т. д.) `claude` отдаёт только при
  включённой телеметрии: его загрузку выключает `DISABLE_TELEMETRY`,

  ошибках, автообновления и `/bug` на список не влияют. Пока AIgram
  остаётся без телеметрии и показывает псевдонимы; включить ли телеметрию
  только для запроса списка моделей — решение пользователя. Решено: нет,
  остаются псевдонимы (раздел 11.10).

Порядок работ:

- 5a — локальный собеседник и его чат в списке (закреп, меню, переходы,
  точки подключения), список сессий, профиль агента с изменением имени и
  фото, блок в настройках. Сессия пока открывается старым видом.
- 5b — нативный вид сессии: лента на `ListWidget`, богатые ответы и
  стриминг, шаги, карточки с кнопками, отмена, ошибки, `ComposeControls` с
  кнопкой модели и «Стопом». Сначала в чате общего агента.
- 5c — панель и палитра на нативном виде, удаление старой ленты,
  переданные сообщения как пересланные и пересылка в чат агента.
- 5d — журнал действий, спайк списка моделей подписки, проверка простоя.
- 5e — проход по всему интерфейсу агента со скриншотами ui-driver в
  отдельной сессии Claude: графические баги и логика взаимодействия.
  Мелкие ошибки исправляются сразу, крупные изменения собираются списком
  на согласование.
- 5f — одобренные доработки после прохода 5e (раздел 11.10).

По умолчанию, без отдельного обсуждения:

- агент в списке — бот (в шапке профиля «бот»), его сообщения приходят от
  его имени, у пользователя — обычные исходящие с галочками;
- уведомлений о сообщениях агента нет, как и раньше: фоновые задачи
  уведомляют своим механизмом (раздел 11.5);
- прочтение, черновики в облаке, «печатает» и запросы профиля для
  собеседника-агента на сервер не уходят, черновик поля ввода хранится
  локально;
- сессии фоновых задач в список сессий не попадают, их открывают из
  задач.

### 11.10 Этап 5f: доработки после прохода 5e

Решено 2026-10-21 по итогам прохода 5e (заметка
`~/.config/aigram/notes/2026-10-21-stage5e-findings.md`, раздел
«Decisions»).

Поле ввода и черновики:

Вопросы:

- Список моделей подписки: остаются псевдонимы, телеметрия `claude`

- Текст ошибки «чат не найден» не меняется.

Порядок работ свободный; мелкие пункты (кнопка «✨Ai», страница задачи,

Уточнения реализации (2026-10-21, при старте 5f):

### 11.11 Этап 6: OpenAI и подписка ChatGPT

Решено 2026-10-22 после обзора документации OpenAI и кода Pi 1.3.
С DevDay 2026 (29 сентября) у OpenAI есть официальный «Sign in with
ChatGPT» с расходом лимита подписки. Коммерческим приложениям нужен
лист ожидания, открытые проекты регистрируются сами: без одобрения,
ключа и секрета. Поэтому AIgram входит напрямую, без `codex`, и не
использует старый неофициальный путь (client id Codex и
`chatgpt.com/backend-api/codex`).

Как устроен вход (документация `developers.openai.com/siwc/
token-sharing-open-source/*`):

- OAuth с PKCE в системном браузере: `https://auth.openai.com/api/
  accounts/authorize`. Первый вход — `client_id=dynamic_agent_client`,
  `agent_name_hint=AIgram` и `ext_agent_host_id` (постоянный
  `urn:uuid:…` этой установки); OpenAI выдаёт свой client id
  `oaiapp_…` в параметре `client_id` ответа, его сохраняют и дальше
  входят с ним. Области: `openid profile email offline_access
  resource.invoke chatgpt.tokens.use.direct`, `resource=https://
  api.openai.com/v1`.
- Ответ браузера — `http://127.0.0.1:1455/auth/callback` (именно
  `127.0.0.1`, не `localhost`). Код меняется на токены POST-формой на
  `https://auth.openai.com/api/accounts/oauth/token`.
- Токен доступа живёт час, токен обновления — 30 дней и меняется при
  каждом обновлении: новую пару сохраняют сразу, обновления одного
  входа идут по одному.
- Запросы — публичный `POST https://api.openai.com/v1/responses` с
  токеном вместо ключа, `store: false`, `stream: true`, история каждый
  раз целиком. Отклоняются `max_output_tokens`, `temperature`, `top_p`,
  `metadata`, `previous_response_id`, `prompt_cache_retention` и
  другие; сообщения роли `system` нельзя, системный промпт идёт в
  `instructions`. Картинки и файлы можно, аудио и видео — нет.
- Модели — `GET /v1/models` с тем же токеном: массив `models`, в списке
  только `visibility: "list"`, показывается `display_name`, в запрос
  уходит `slug`.
- Остаток лимита API не сообщает. Ошибки с кодами
  `subscription_sharing_*` (лимит, план не подходит, вход недействителен)
  останавливают ход, OpenAI сама на оплату по ключу не переключает.
- Правила интерфейса OpenAI: кнопка «Continue with ChatGPT» с логотипом,
  подпись об использовании плана ChatGPT у выбора модели, ссылка
  «Manage usage» на `https://chatgpt.com/settings/usage`.

Решения пользователя:

- Вход напрямую; `codex` как движок не делается (раздел 13).
- В «Добавить модель» появляется «OpenAI» с двумя способами, как у
  Anthropic: «Подписка ChatGPT» и «Ключ API». Оба идут через новый
  адаптер Responses API. У ключа модели берутся из `/v1/models`, цены —
  из встроенной таблицы, их можно поправить.
- У профилей OpenAI есть «Размышления»: «Как у модели» и уровни, которые
  модель умеет (`none`, `low`, `medium`, `high`, `xhigh`, `max`). В чате
  показывается краткий пересказ размышлений (`reasoning.summary:
  "auto"`), между шагами хода размышления возвращаются модели в
  зашифрованном виде (`include: ["reasoning.encrypted_content"]`).
- Подпись: в меню моделей под кнопкой модели у каждого профиля вторая
  строка с сервисом и моделью («Подписка ChatGPT · gpt-6.1-sol»,
  «OpenRouter · z-ai/glm-5.3-flash»), так же в списке моделей в
  настройках. «Управление лимитом» — в окне профиля подписки, в
  «Расходах» настроек и в ошибке лимита.
- Если браузер не вернулся в AIgram (порт 1455 занят входом Codex,
  браузер на другом устройстве), в окне входа можно вставить адрес из
  адресной строки браузера; AIgram проверяет `state` и завершает вход.
- Лимит исчерпан: ход кончается ошибкой «Лимит подписки ChatGPT
  исчерпан» с кнопками «Управление лимитом» (открывает страницу
  использования ChatGPT) и «Сменить модель» (меню моделей). Фоновая
  задача на этой модели пишет ошибку в журнал прогона и ждёт следующего
  срабатывания.

По умолчанию, без отдельного обсуждения:

- Вход один на все профили подписки ChatGPT, как у подписки Claude:
  следующий профиль шаг входа пропускает. В окне профиля — «Вход:
  email · план» и «Выйти» (отзывает токен обновления через
  `revocation_endpoint` из `/.well-known/openid-configuration` и
  стирает токены; client id и id установки остаются для следующего
  входа).
- Токены лежат в зашифрованных настройках агента (`Storage::Domain`)
  вместе с профилями. Сохранение профилей никогда не перезаписывает
  токены ChatGPT старой копией: их меняют только вход, выход и
  обновление токена.
- Токен обновляется за 3 минуты до конца срока; на ответ 401 запрос
  один раз повторяется после обновления. Окончательная ошибка
  обновления (`invalid_grant` и подобные) стирает токены: ход кончается
  ошибкой «Войдите в ChatGPT снова» с кнопкой «Настройки модели».
- Окно контекста профилей OpenAI — 272 тысячи токенов (дальше API
  берёт двойную цену), если модель не сообщает меньшее.
- Возможности: картинки и файлы (PDF) модель получает сама, аудио и
  видео — через модель для медиа.
- `prompt_cache_key` — ключ сессии, как у OpenAI по Chat Completions.
- Подписка: токены считаются, денег нет, лимиты фона — в токенах (как у
  подписки Claude).
- Перенос: профили «Другой провайдер» с адресом `api.openai.com`
  остаются как есть.
- Кнопка входа — «Continue with ChatGPT» с логотипом ChatGPT из
  материалов OpenAI.

### 11.12 Аудит безопасности (2026-10-22)

Аудит уровней разрешений агента нашёл обходы ограничений; заметка с
находками — `~/.config/aigram/notes/2026-10-22-agent-security-audit.md`.
Исправления без отдельного решения:

- Фоновая задача читает только чаты своих рамок: списки чатов, общий
  поиск, контакты и заблокированные показывают лишь чаты рамок,
  пересылка из чата вне рамок — ошибка.
- Чтения MTProto с внешним действием (предпросмотр ссылки,
  `messages.getWebPage`, кнопки ботов, RTMP-ключ, проверка загрузки
  файла ботом) идут карточкой. Параметры, тратящие звёзды
  (`allow_paid_stars`, `allow_paid_floodskip`), отклоняются всегда.
  Числовые id чатов и людей в параметрах проверяются, как ссылки на
  чаты; из ответов вычищаются и скрытые папки, и полные сведения скрытых
  чатов.
- «Прочитано» отправляет отметки о прочтении, поэтому это видимое
  другим действие: карточка, а в фоне — без вопроса, только если
  инструмент в рамках задачи.
- Правило taint для исходящего действия без чатов: после чтения чужого
  оно всегда спрашивает карточкой без «разрешать до конца поручения».
- Скрытая папка по правилу (все каналы и т. п.) прячет и чат, историю
  которого клиент ещё не загружал.
- Выход из ChatGPT во время обновления токена больше не возвращает
  вход; токен ChatGPT уходит только на `https://api.openai.com/`, а
  ключи и токены не идут за переадресацией на другой адрес.
- Офисные документы распаковываются не больше чем на 64 МБ в сумме.
- Задачи чата, скрытого от агента, не запускаются и по расписанию.
- Подсказка палитры об открытом чате называет его id, без названия:
  название пишут другие люди, модель узнаёт его инструментом.

Решения пользователя:

- Память: пока сессия не читала чужого, запись и правка памяти идут как
  раньше, строкой «Запомнил» с «Отменить». После чтения чужого
  (сообщения, файлы, посты, переданные сообщения) запись и правка
  спрашивают карточкой «Запомнить».
- «Разрешать до конца поручения» привязано к целям: разрешение
  покрывает только те же чаты, людей, сообщения и ссылки, что были
  отмечены на одобренной карточке. Карточка без целей (профиль, создание
  и вступление в чат, метод MTProto без чатов и т. п.) разрешает только
  точно такое же действие.
- Человек, чей личный чат скрыт, скрыт и в действиях: инструменты
  администрирования и контактов его не принимают, списки контактов и
  заблокированных его пропускают. В участниках групп и авторах
  сообщений люди остаются.
- Для правила taint исходящими считаются все действия с текстом или
  картинкой, которые видят другие: кроме отправки, пересылки, файлов и
  `call_method` ещё правка сообщения, профиль (имя, «О себе», фото),
  название и описание чата, фото чата, создание чата, названия
  пригласительных ссылок и добавление контакта. В агенте чата правило
  taint не действует (раздел 6.2).
- Лимит «действий в час» фоновой задачи считает каждый чат и каждого
  человека вызова (отправка в 10 чатов — 10 действий), а после
  перезапуска клиента счётчик часа восстанавливается из журнала
  прогонов.
- Дневные лимиты расходов фона по-прежнему проверяются до и после
  прогона.
- Оставлены как принятый риск: `open` чата отмечает видимые сообщения
  прочитанными, как при обычном открытии; папка агента одна на все
  аккаунты.

### 11.13 Этап 7: понятные инструменты

Решено 2026-10-22 по исследованию того, как другие агенты помогают модели
выбрать инструмент (Pi, opencode, Cline, Hermes Agent, OpenClaw, статьи
Anthropic и OpenAI; заметка
`~/.config/aigram/notes/2026-10-22-tool-prompting-research.md`) и по
выгрузке сессий пользователя. Что показали сессии:

- модель не видит инструментов групп и решает, что действие невозможно
  (скачивание файлов до `load_tools files`), или выдумывает имена
  (`get_history`, `get_all_chats`);
- поиск отдаёт посты целиком: вопрос про почту преподавателя стоил 22
  поиска и 549 тыс. входных токенов; модель перебирала написания одного
  слова, не зная, что Telegram ищет целые слова и их начала;
- нет чтения истории за дату (обход — поиск по слову «а»), поиска по типу
  медиа (мемы — картинки без текста), поиска в нескольких чатах и ответа
  на сообщение в черновике агента чата;
- модель утверждает то, чего нет в результате («черновик привязан к
  мему», «общий агент умеет удалять файлы»);
- у GLM в размышлениях видны служебные токены формата вызовов.

Решения:

- **Каталог в системном промпте.** У каждого инструмента — строка до 60
  символов (`snippet`). Промпт перечисляет все инструменты режима,
  включая инструменты групп с пометкой группы, по разделам: найти и
  прочитать, действия с сообщениями, состояние чатов, медиа и файлы,
  память и задачи, администрирование, контакты, профиль, ИИ Telegram,
  MTProto. Для каждой группы — когда её подключать. Каталог не меняется
  в течение сессии (кэш промптов).
- **Один промпт для всех моделей, как в Pi**, с общими правилами:
  сначала каталог, потом «не могу» (инструмент группы подключается
  `load_tools`); не выдумывать имена инструментов, id и возможности
  другого агента; утверждать только то, что показал результат
  инструмента; действия с карточкой спрашивают пользователя сами, не
  переспрашивать в тексте и не повторять отклонённое другим путём.
  Добавка под семейство моделей — только когда выгрузки показали провал
  этого семейства. Первая — для GLM (по id модели профиля): вызывать
  инструменты только в ответе, не внутри размышлений и не текстом.
- **Поиск** (`search_messages`):
  - несколько запросов за вызов (`queries`, до 5), результаты
    объединены без повторов, у находки — какой запрос сработал;
  - несколько чатов (`chats`) или типы чатов (личные, группы, каналы,
    боты), фильтр по типу медиа (фото, видео, файлы, голосовые, кружки,
    музыка, ссылки, GIF), даты; слово не обязательно, когда задан фильтр
    медиа или дат;
  - находка короткая: чат, id, дата, автор, тип медиа, ~300 символов
    вокруг совпадения и длина полного текста;
  - соседние сообщения по желанию (`context` 0–2);
  - находки, уже показанные в этом ходе, приходят только списком id;
  - режим обзора: сколько совпадений в каждом чате;
  - в описании: как ищет Telegram (целые слова и их начала, не части
    слов; почту искать по домену), совет добавлять латинское написание
    имён и логинов в `queries`, смена подхода после 2–3 пустых поисков.
- **Чтение истории** (`read_history`): параметр `ids` — сообщения
  целиком; чтение с даты; очень длинные тексты в обычном чтении
  обрезаются с пометкой и длиной.
- **Список чатов** (`list_chats`): поиск по названию.
- **Медиа**: `view_media` по списку сообщений (до 10 за вызов).
- **Черновик агента чата** (`set_draft`): ответ на сообщение
  (`reply_to`).
- **Повтор вызова:** второй одинаковый вызов чтения в одном ходе не
  выполняется, модель получает «уже вызывал, результат выше (id вызова),
  смени подход». Действия не трогаются — их стерегут карточки.
- **`[Context]` к каждому сообщению:** местные дата, время, день недели
  и часовой пояс; подключённые группы; открытая тема форума (и в
  палитре); ждущие карточки сессии.
- **`load_tools`** принимает и группу, и поисковый запрос (BM25 по имени,
  строке каталога, описанию, параметрам и группе; находкой считается
  только инструмент с самым редким словом запроса; при промахе — список
  групп). Группы остаются.
- **Примеры вызовов — только в описаниях** сложных инструментов
  (`create_task`, `search_messages`, `set_chat_permissions`,
  `call_method`), без рецептов в промпте.
- Транслитерация имён — только совет в описании поиска.

По умолчанию, без отдельного обсуждения:

- описания инструментов: ключевое правило первым, затем когда
  использовать, когда нет и что взять вместо; пары, которые легко
  спутать (`set_pinned` и `pin_message`, `delete_messages` и
  `delete_chat_messages`, `transcribe_voice` и `listen_audio`,
  `memory_add` и `create_task` для «напомни»), называют друг друга;
- ошибки учат: неизвестный инструмент — ближайшие имена и группа,
  неверные аргументы — ожидаемый формат;
- память записывается фактами о пользователе, не командами себе;
- выгрузка сессий для отладки («Export sessions for debugging» в
  настройках агента, ветка `agent-export`) входит в этап.

Не делаем: удаление файлов папки агента, переименование инструментов,
урезанный набор для маленьких моделей (после новых выгрузок), выполнение
кода моделью (нужен рантайм).

Порядок работ: 7a — чистое ядро (каталог и правила в промпте, добавка
GLM, BM25 по инструментам, подсказка ближайших имён, тесты); 7b — поиск и
чтение истории; 7c — медиа списком, ответ в черновике, поиск чатов по
названию; 7d — реестр и сессия (`load_tools` с запросом, повторы,
ошибки, `[Context]`); 7e — строки каталога и описания всех инструментов;
7f — проверка на выгрузках и живых безопасных запросах.

## 12. Риски и открытые вопросы

- Протокол Claude Code может меняться между версиями, а использование
  подписки в стороннем хосте Anthropic может закрыть технически.
- Anthropic объявляла (май 2026) и отложила отдельный месячный кредит для
  `claude -p` и Agent SDK вместо лимитов подписки; если его введут,
  подписка в AIgram будет тратить этот кредит.
- Качество вызова инструментов у локальных моделей. Нужны минимальные
  требования к модели. Возможно, потребуется резервный режим вызова
  инструментов через JSON в тексте для моделей без нативной поддержки.
- Автоматические массовые действия могут привести к ограничениям аккаунта со
  стороны Telegram.
- Провайдеры Anthropic и OpenAI недоступны из части регионов, без
  SOCKS/HTTP-прокси агент там не работает.
- Расход подписки ChatGPT в сторонних программах OpenAI называет
  предварительной версией: список отклоняемых полей и коды ошибок могут
  меняться.
- Шифрование ключей на уровне приложения (раздел 10).
