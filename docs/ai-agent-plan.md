# AIgram: ИИ-агент внутри клиента

Документ фиксирует решения дизайн-сессии от 2026-10-18 и уточнения перед
этапами. Этап 0 завершён.
Ссылки на код даны по символам и путям относительно `Telegram/SourceFiles/`.

## 1. Цель и инвариант

Агент выполняет по текстовому описанию любые действия, доступные пользователю
в клиенте, от его лица: читает и ищет переписку, пишет, пересылает, управляет
чатами, папками, профилем и настройками, а также работает в фоне по заданным
правилам.

Инвариант: каждое действие агента проходит через единый реестр инструментов
внутри клиента и через единый шлюз политики (область доступа режима,
исключённые чаты, уровни риска, подтверждения, рамки фоновых задач, бюджеты).
Ни один движок, включая внешний Claude Code, не обращается к Telegram в обход
реестра, и ни один инструмент не выполняется в обход шлюза.

Ограничение «лёгкости»: в AIgram не встраиваются Node, Python, Bun или другие
рантаймы. Всё, что поставляется с клиентом, написано на C++ поверх Qt и
существующих библиотек.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Аудитория | Открытый форк для всех желающих. Юридическая сторона (условия Anthropic и Telegram) сознательно не рассматривается |
| Синхронизация с upstream | Регулярные ребейзы. Код агента живёт в отдельной области, в существующих файлах только тонкие точки подключения |
| Движок | Свой лёгкий цикл агента на C++ |
| Провайдеры | Anthropic Messages API и OpenAI-совместимый Chat Completions (OpenAI, OpenRouter, DeepSeek, Gemini через совместимый эндпоинт, Ollama, LM Studio, vLLM) |
| Первый адаптер | OpenAI-совместимый облачный |
| Подписка Claude | Необязательный второй движок: установленный пользователем бинарник `claude`, к которому AIgram подключается по протоколу Agent SDK |
| Режимы | Два режима: общий агент с доступом ко всему и агент чата, ограниченный одним чатом (раздел 3) |
| Общий агент в интерфейсе | Закреплённая строка «✦ Агент» над закреплёнными чатами. Открывается в центральной колонке как чат. Настоящим чатом Telegram не является |
| Агент чата в интерфейсе | Боковая панель в третьей колонке |
| Палитра команд | Слой поверх окна, быстрый вход в общего агента. Каждая команда сохраняется сессией общего агента |
| Автономность | Интерактивный режим и фоновые задачи |
| Права в диалоге | Уровни риска (раздел 6.1). Разрешение из карточки действует до конца поручения, для того же вида действия и тех же чатов |
| Права в фоне | Рамки задаются при создании задачи, всё вне рамок уходит в очередь подтверждений |
| Запуск фоновых задач | Структурный фильтр без модели, модель вызывается только при совпадении |
| Где работает фон | Пока запущен клиент, в том числе свёрнутый в трей |
| Уведомления фона | Настраиваются в задаче. По умолчанию тихое уведомление о каждом видимом другим действии. Очередь подтверждений и паузы по лимиту уведомляют всегда |
| Доступ к чатам | Все, кроме исключённых пользователем |
| Универсальная MTProto-команда | Только у общего агента, включена всегда, с подтверждениями и жёстким чёрным списком |
| Память | У каждого чата своя память, у общего агента своя. Общий агент может читать память чатов. Фоновые задачи память не видят |
| Общие инструкции | Поле в настройках. Пишет его только пользователь, видят все агенты и фоновые задачи |
| Несколько аккаунтов | Сессии, задачи, память и права — свои у каждого аккаунта. Провайдеры, ключи и общие инструкции — на всё приложение |
| Медиа | Текст, фото (если модель их видит) и голосовые через расшифровку Telegram |
| Локальные файлы | Только явно переданные пользователем и папка агента |
| Расходы | Счётчик и лимиты, отдельная модель для фона |
| Пометка сообщений агента | Не делается. Если нужна подпись, пользователь просит её у агента сам |
| Отправка в чат агентом чата | Черновик в поле ввода этого чата |
| Отправка в чат общим агентом | Карточка с кнопками «Отправить», «В черновик», «Отклонить» |
| Хранение | Локально в зашифрованном tdata |

## 3. Режимы

### 3.1 Общий агент

- Закреплённая строка «✦ Агент» стоит над всеми закреплёнными чатами и
  показывает счётчик ожидающих подтверждений. Строка открывает экран агента в
  центральной колонке: ленту сессии и поле ввода.
- Список сессий. У каждой сессии видны затронутые чаты.
- Доступ ко всему, кроме исключённых чатов: любые чаты, навигация по
  настройкам, универсальная команда, фоновые задачи для любых чатов.
- Неявного контекста нет: какой чат открыт, общему агенту неважно, чаты
  называются в запросе.
- Палитра по горячей клавише — тот же общий агент поверх окна для разовых
  команд. Результат каждой команды сохраняется как сессия.
- Пункт «Передать агенту» в меню сообщения отправляет выделенные сообщения в
  новую сессию общего агента. Это замена пересылке, так как настоящим чатом
  «✦ Агент» не является.

### 3.2 Агент чата

- Кнопка ✦ в шапке чата открывает боковую панель.
- Сессия навсегда привязана к чату, в котором её начали. Панель показывает
  только сессии этого чата. При переключении чата панель переключается на
  сессии нового чата, а начатая работа доделывается в фоне.
- Доступно только содержимое этого чата:
  - история, поиск, участники;
  - сводка и перевод серверным ИИ Telegram;
  - черновик в поле ввода, правка и удаление своих сообщений;
  - реакции, закреп, звук, архив, папка;
  - администрирование этого чата;
  - фоновые задачи этого чата.
- Других чатов, навигации по настройкам и универсальной команды нет. Если
  просьба выходит за пределы чата, агент предлагает «Продолжить в общем
  агенте» и передаёт туда сессию как недоверенный контекст.
- В чат агент пишет только черновиком в поле ввода (`History::setLocalDraft`),
  с ответом на нужное сообщение. Если пользователь уже ушёл в другой чат,
  черновик остаётся в этом чате и виден в списке чатов как «Черновик: …».
- Изоляция встроена в сам режим: инструкция, подброшенная участником чата, не
  может ни прочитать другие чаты, ни написать в них.

## 4. Архитектура

```text
UI: экран «✦ Агент», панель чата, палитра, карточки, черновики
  |
Agent::Session        режим и область доступа, история, потоковый вывод,
  |                   память, учёт стоимости
  |  интерфейс Engine
  +-- NativeEngine                 свой цикл агента
  |     +-- OpenAiCompatAdapter    POST {base}/chat/completions, SSE
  |     +-- AnthropicAdapter       POST /v1/messages, SSE, кэш промптов
  +-- ClaudeCodeEngine (опция)     QProcess `claude -p`, stream-json,
                                   can_use_tool / mcp_message
  |  вызов инструмента
Agent::PolicyGate     область режима, исключения, уровни риска, taint,
  |                   рамки задач, бюджеты
Agent::ToolRegistry   ApiWrap, Data::Session, Core::DeepLinks::Router,
                      Settings::Builder::SearchRegistry, MTP-запросы
```

Область доступа (весь аккаунт или один чат) задаётся при создании
`Agent::Session` и проверяется в `PolicyGate`. Набор инструментов в контексте
модели зависит от режима, но фильтр в шлюзе — главная защита: даже вызов
инструмента, которого нет в контексте, проверяется по области.

### 4.1 Размещение кода

Новая область атласа `agent` с путями `SourceFiles/agent/` и своей картой
`SourceFiles/agent/AGENTS.md`. Запись в `SourceFiles/AGENTS.md` добавляется в
той же задаче, которая создаёт область.

- `agent/engine/` — интерфейс движка, свой цикл, адаптеры провайдеров, движок
  Claude Code.
- `agent/tools/` — реестр, группы инструментов, реализации.
- `agent/policy/` — области, уровни риска, исключения, taint, рамки, бюджеты.
- `agent/tasks/` — фоновые задачи, фильтры, планировщик, очередь подтверждений.
- `agent/storage/` — зашифрованное хранение сессий, памяти, задач, исключений.
- `agent/ui/` — экран общего агента, панель чата, палитра, карточки, раздел
  настроек.

Точки подключения в существующем коде (держать минимальными):

- **Строка «✦ Агент» в списке чатов** — механизм свёрнутых строк над списком
  (`CollapsedRow` в `dialogs/dialogs_inner_widget.h`).
- **Экран общего агента** — свой `Window::SectionWidget` и
  `Window::SectionMemento` (`window/section_widget.h`) в центральной колонке.
- **Панель агента чата** — `Info::Section::Type::Agent` и тег в `Info::Key`
  (`info/info_controller.h`). Прецедент секции без пира — теги
  `Downloads::Tag` и `Stories::Tag`.
- **Кнопка ✦** в шапке чата (`history/view/history_view_top_bar_widget*`).
- **Горячие клавиши** — новые значения `Shortcuts::Command`
  (`core/shortcuts.h`) для панели и палитры.
- **Меню чата и сообщения** — «Скрыть от агента» в `Filler`
  (`window/window_peer_menu.cpp`) и «Передать агенту» в меню сообщения
  (`history/view/history_view_context_menu.cpp`).
- **Владение состоянием.** Состояние агента на уровне аккаунта — компонент
  `Main::Session`. Провайдеры, ключи и общие инструкции — на уровне
  приложения.
- **Фоновые триггеры** подписываются на `Data::Session::newItemAdded()` без
  правок чужого кода.

### 4.2 Интерфейс движка

Движок принимает сообщение пользователя, умеет прерываться и отдаёт поток
событий: дельты текста, запрос вызова инструмента, результат, расход токенов,
ошибку и завершение хода. Внутреннее представление диалога — блоки `text`,
`image`, `tool_use` и `tool_result`. Каждый адаптер переводит его в формат
своего провайдера. UI и `Agent::Session` от выбора движка не зависят.

### 4.3 Свой цикл

- HTTP через `QNetworkAccessManager`. `core/sandbox.cpp` уже ставит SOCKS5/HTTP
  прокси клиента прокси всего приложения, поэтому запросы к провайдерам идут
  через него. MTProxy HTTPS не переносит, и в этом случае нужен отдельный
  SOCKS/HTTP-прокси.
- Возможности модели (вызов инструментов, зрение, размер контекста) берутся из
  ответа `/models` провайдера, если он их сообщает, иначе задаются в настройках.
- Контекстом управляет клиент, потому что серверные функции есть не у всех
  провайдеров:
  - оценка размера;
  - сжатие старых ходов в сводку той же или более дешёвой моделью;
  - обрезка больших результатов инструментов с продолжением по запросу.
- Для провайдера Anthropic включается кэш промптов. Чтобы кэш работал, порядок
  и текст инструментов и системного промпта в течение сессии не меняются.
- Каталог инструментов состоит из компактного ядра, которое всегда в контексте,
  и групп, подгружаемых метаинструментом `load_tools(group)`. Это нужно
  локальным моделям с контекстом 8–32 тысячи токенов. Подгруженные схемы
  дописываются в конец и не перестраивают уже отправленные.

### 4.4 Движок Claude Code (этап 4)

- AIgram находит `claude` в `PATH` или по пути из настроек и показывает способ
  входа из `claude auth status`. AIgram никогда не читает и не хранит учётные
  данные Claude: вход выполняет сам пользователь командой `claude auth login`.
- Запуск в режиме `-p` с `--input-format stream-json --output-format
  stream-json --verbose --include-partial-messages`, без встроенных
  инструментов (`--tools ""`), со своим системным промптом
  (`--system-prompt-file`). От пользовательских `~/.claude` запуск изолирован
  через `--strict-mcp-config` и `--setting-sources`. `--bare` не подходит:
  в этом режиме не читается вход по подписке.
- Инструменты отдаются как MCP-сервер внутри процесса (`type: "sdk"`). CLI
  пересылает JSON-RPC в управляющем запросе `mcp_message`, AIgram отвечает
  через `ToolRegistry` с учётом области сессии. Запрос `can_use_tool`
  направляется в `PolicyGate`. Хост отправляет `initialize`, `interrupt` и
  `set_model`.
- Прокси приложения передаётся процессу через `HTTPS_PROXY`.
- Риск: управляющий протокол публично не документирован и известен по
  исходникам Agent SDK. Нужна минимальная поддерживаемая версия и проверка
  поля `capabilities` в событии `system/init`. Точный набор флагов изоляции
  проверяется спайком в начале этапа.

## 5. Инструменты

### 5.1 Ядро

Всегда в контексте общего агента:

- `get_context` — аккаунт, текущее время;
- `list_chats` — фильтры по папке, непрочитанным, типу;
- `read_history` — диапазон или окно вокруг сообщения, с пагинацией;
- `search_messages` — глобально или в чате, по отправителю и датам;
- `get_peer_info`;
- `send_message` — через карточку, с вариантом «в черновик»;
- `forward_messages`, `edit_message`, `delete_messages`;
- `react`, `mark_read`, `set_mute`, `set_archived`, `set_pinned`;
- `find_setting` и `open` — навигация, раздел 5.3;
- `memory` — своя память и чтение памяти чатов;
- `load_tools`.

У агента чата те же инструменты, но без параметра чата: целью всегда
является его чат. Списка чатов, глобального поиска, навигации и чтения чужой
памяти у него нет.

### 5.2 Группы

- **Администрирование чатов:** создание групп и каналов (только общий агент),
  приглашения, ссылки, участники, админы, ограничения.
- **Папки.**
- **Контакты и блокировки.**
- **Профиль:** имя, описание, фото, статус. Только общий агент.
- **Медиа:** просмотр фото моделью, расшифровка голосовых через
  `Api::Transcribes`, скачивание в папку агента, отправка переданных файлов.
- **Серверный ИИ Telegram:** `messages.summarizeText`,
  `messages.translateText`, `messages.composeMessageWithAI`.
- **Задачи:** создание, список, пауза и удаление фоновых задач. Агент чата
  управляет только задачами своего чата.
- **MTProto:** раздел 5.4.

### 5.3 Навигация

Только у общего агента. `Settings::Builder::SearchRegistry::collectAll()`
(`settings/settings_builder.h`) отдаёт по каждому пункту настроек заголовок,
ключевые слова, раздел, состояние галочки и deep link.
`Core::DeepLinks::Router` (`core/deep_links/`) открывает раздел и
подсвечивает конкретный элемент. Вместе они покрывают длинный хвост редких
действий без отдельного кода: агент находит место и открывает его, а последний
клик делает пользователь.

### 5.4 Универсальная MTProto-команда

- Доступна только общему агенту и только в интерактивных сессиях.
- Каталог методов генерируется при сборке из `mtproto/scheme/api.tl`. В
  контексте лежит только компактный список имён. Схему конкретного метода
  агент получает инструментом `describe_method`.
- Пиры передаются понятными ссылками (id, @username). `InputPeer` и
  `access_hash` собирает инструмент по данным `Data::Session`, модель их не
  видит. Исключённые чаты в параметрах отклоняются, а из ответов
  вычищаются.
- Методы-чтения (`*.get*`, `*.search*`, `*.check*`) выполняются без
  подтверждения. Всё остальное идёт через карточку с человеческим описанием
  действия.
- Чёрный список выполняется всегда, без исключений: удаление аккаунта,
  `auth.*`, пароль и его восстановление, сброс сессий, платежи, Stars, подарки
  и кошелёк.
- Ответ сериализуется из TL в JSON для модели и применяется к клиенту так же,
  как обычные ответы (например, `Updates` через `ApiWrap::applyUpdates`), чтобы
  интерфейс оставался согласованным.

### 5.5 Представление данных для модели

Сообщение передаётся компактно: id, дата, отправитель, текст с сущностями в
markdown, краткое описание медиа. Разбор из `export/data/export_data_types.h`
(`ParseMessage`, `ParseDialogsInfo`) переиспользуется там, где подходит.
Длинные результаты обрезаются, продолжение запрашивается пагинацией. Чтение
агентом не помечает сообщения прочитанными.

## 6. Политика

### 6.1 Уровни риска в диалоге

| Уровень | Действия | Поведение |
|---|---|---|
| Чтение и навигация | список чатов, история, поиск, профили, открытие экранов, методы-чтения MTProto | без подтверждения |
| Обратимые мелочи | без звука, архив, закреп, папки, прочитано | без подтверждения, с записью в журнал и плашкой «Отменить» |
| Видимое другим или необратимое | отправка (у агента чата — только черновик), пересылка, реакции, редактирование, удаление, вступление и выход, профиль, администрирование, прочие методы MTProto | карточка подтверждения |
| Запрещённое | чёрный список из раздела 5.4 | никогда |

В карточке есть галочка «разрешать такое до конца поручения». Разрешение
действует только до конца текущей просьбы пользователя, только для того же
вида действия и только для тех же чатов.

### 6.2 Правило taint

Действует для общего агента. Если в поручении агент уже прочитал контент,
автор которого не пользователь (чужие сообщения, посты каналов, файлы, сессию,
перенесённую из агента чата), то отправка или пересылка в чат, который
пользователь не называл в запросе, всегда требует подтверждения. Разрешение до
конца поручения это правило не снимает. Недоверенный контент в результатах
инструментов размечается как данные, а не как инструкции. Агенту чата это
правило не нужно: писать за пределы своего чата он не может.

### 6.3 Исключённые чаты

Список исключённых чатов и папок ведётся отдельно для каждого аккаунта и
задаётся из меню чата. Исключённые чаты не видны ни одному инструменту, включая
результаты поиска и ответы универсальной команды. Писать в них запрещено.
Панель агента чата в исключённом чате недоступна.

### 6.4 Рамки фоновой задачи

Задача хранит, что ей разрешено: какие инструменты, в какие чаты, сколько
действий в час и какой бюджет. Всё, что выходит за рамки, попадает в очередь
подтверждений с уведомлением. Универсальная команда, память и навигация в фоне
недоступны. Рамки задачи, созданной из панели агента чата, ограничены этим
чатом.

### 6.5 Бюджеты

Расход токенов и примерная стоимость считаются по сессиям и задачам. У фона
есть дневной лимит и лимит на каждую задачу; при превышении задача ставится на
паузу с уведомлением. Массовые операции учитывают `FLOOD_WAIT` и ограничивают
темп, чтобы не получить ограничения аккаунта за спам.

## 7. Память и инструкции

- **Память чата.** У каждого чата своя память. Агент чата читает и дополняет
  её в интерактивных сессиях. Пользователь видит и правит её в панели.
- **Память общего агента** — своя. Общий агент дополняет её и при
  необходимости читает память любого чата. Писать в память чатов он не может.
- **Общие инструкции** — поле в настройках («отвечай кратко», «без эмодзи»).
  Пишет его только пользователь, видят все агенты и фоновые задачи.
- **Фоновые задачи** памяти не видят. Им доступны только собственная
  инструкция и общие инструкции, поэтому собеседник не может выудить
  через автоответчик заметки о себе.

## 8. Фоновые задачи

- **Создание.** Задачу создают из общего агента (для любых чатов) или из
  панели агента чата (только для этого чата). Агент предлагает структурное
  правило, а карточка показывает фильтр, промпт действия, рамки, модель,
  бюджет и режим уведомлений. Задача начинает работать только после одобрения.
- **Триггеры:**
  - входящее сообщение по фильтру (чаты, отправители, ключевые слова или
    регулярное выражение, тип медиа, упоминания, временное окно);
  - расписание;
  - разовый таймер.
- **Фильтр** проверяется на `Data::Session::newItemAdded()` без модели. Только
  совпадение запускает прогон агента с промптом задачи, а сработавшее сообщение
  передаётся как недоверенные данные.
- **Уведомления.** По умолчанию каждое видимое другим действие приходит тихим
  уведомлением; у задачи есть режим «только журнал». Очередь подтверждений и
  пауза по лимиту уведомляют всегда.
- **Списки.** Полный список задач живёт в общем агенте, задачи чата видны ещё
  и в его панели.
- **Время работы.** Задачи работают, пока запущен клиент. Пропущенные события
  по умолчанию не догоняются; у задачи есть опция обработать пропущенное при
  запуске.
- **Очередь.** Внутри одной задачи прогоны идут по одному, повторы
  отбрасываются. Элементы очереди подтверждений со временем устаревают.

## 9. Интерфейс

- **Экран общего агента** открывается из строки «✦ Агент» в центральной
  колонке:
  - лента сессии и поле ввода;
  - список сессий с затронутыми чатами;
  - вкладки задач, памяти и очереди подтверждений;
  - журнал действий с отменой.
- **Панель агента чата** — секция Info в третьей колонке: сессии этого чата,
  его память и задачи. В узком окне панель открывается слоем поверх чата.
- **Палитра** — слой поверх всего главного окна, не отдельное окно ОС.
- **Ответ агента** рендерится как markdown средствами `iv/markdown`. Вызовы
  инструментов показываются сворачиваемыми строками, их можно раскрыть.
  Карточки подтверждений позволяют поправить текст перед выполнением.
- **Раздел настроек «Агент»:**
  - провайдеры — адрес, ключ, модели;
  - роли моделей — основная, фоновая, вспомогательная для сжатия;
  - общие инструкции, лимиты, исключённые чаты;
  - путь к `claude`.

## 10. Хранение

- Данные аккаунта (сессии, память чатов и общего агента, задачи, исключения,
  статистика расходов) лежат в зашифрованном файле аккаунта
  (`Storage::details::EncryptedDescriptor`, `PrepareEncrypted` в
  `storage/details/storage_file_utilities.h`) и защищены локальным паролем,
  если он задан.
- Провайдеры, ключи и общие инструкции хранятся на уровне приложения в
  отдельном зашифрованном файле домена рядом с ключами кошелька
  (`Storage::Domain::readAgentSettings()`). Он шифруется локальным ключом и
  без локального пароля не расшифровывается, если пароль задан.
- Папка агента по умолчанию — `AIgram Agent` внутри папки загрузок Telegram.

## 11. Этапы

0. **Фундамент:**
   - инициализация сабмодулей и рабочая Debug-сборка;
   - область `agent/` и запись в атласе;
   - интерфейс движка, свой цикл и `OpenAiCompatAdapter` с потоковым выводом
     и инструментами;
   - настройки провайдеров, хранение.
1. **Интерактивный агент:**
   - панель агента чата, затем экран общего агента со строкой в списке чатов;
   - ядро инструментов и навигация;
   - `PolicyGate` с областями, уровнями риска, taint и исключениями;
   - карточки и черновики;
   - память, общие инструкции, счётчик расходов.
2. **Фоновые задачи:** триггеры, расписание, рамки, очередь подтверждений,
   уведомления, лимиты.
3. **Расширения:** универсальная MTProto-команда, фото и голосовые, папка
   агента, палитра, «Передать агенту», группы инструментов кроме «Папок»
   (администрирование, контакты, профиль, серверный ИИ Telegram).
4. **Второй адаптер и подписка:** `AnthropicAdapter` с кэшем промптов,
   `ClaudeCodeEngine`.

### 11.1 Уточнения этапа 1

Этап 1 делится на три подэтапа, после каждого — вливание в `ai-agent` и
ручная проверка по чек-листу:

- **1a:** `Agent::Session` и `Agent::Manager`, `PolicyGate`, хранение
  сессий, управление контекстом, инструменты чтения своего чата, панель
  агента чата с кнопкой ✦.
- **1b:** инструменты действий, карточки, черновики, `load_tools` с группой
  «Папки», экран общего агента со строкой «✦ Агент», общие инструменты
  чтения и навигация, «Продолжить в общем агенте».
- **1c:** память, общие инструкции в промпте, исключённые чаты, счётчик
  расходов.

Решения:

- Сессии хранятся бессрочно, по файлу на сессию в зашифрованном хранилище
  аккаунта, удаляются только пользователем.
- Контекст: результаты инструментов обрезаются, а при заполнении ~70% окна
  модели старые ходы сжимаются в сводку той же моделью. Полная лента для
  пользователя сохраняется. Ошибка переполнения контекста вызывает сжатие и
  повтор хода.
- Название сессии придумывает модель отдельным коротким запросом после
  первого хода; пользователь может переименовать.
- Сообщение, отправленное во время хода, ждёт в очереди. «Стоп» прерывает
  ход и очищает очередь.
- Лента — свой виджет: пузыри пользователя, ответы через `iv/markdown`,
  сворачиваемые строки инструментов, карточки. В шапке «Новая сессия» и
  «История»; история открывает список сессий и вкладку памяти.
- Агент чата при старте видит только сводку чата и сам читает историю. В
  форуме сессия привязана ко всему форуму, а открытая тема передаётся
  подсказкой к сообщению.
- Черновик агента чата: при пустом поле ввода ставится сразу, при непустом —
  карточка «Заменить» / «Дописать» / «Отмена».
- Обратимые действия отменяются кнопкой «Отменить» у строки в ленте и
  «Отменить все» для хода. Общий журнал — в этапе 2.
- Taint: чат назван, если его @username, ссылка t.me или название есть в
  тексте поручения либо он вставлен @-автодополнением. Taint держится до
  конца сессии, а не одного поручения: прочитанный чужой контент остаётся в
  контексте модели.
- Память — список коротких фактов с id (`add` / `update` / `remove`), до 50
  записей, целиком в системном промпте при старте сессии.
- Расходы: токены всегда, деньги — если провайдер сообщает стоимость или в
  модели задана цена за миллион токенов. Лимиты — в этапе 2.
- Строка «✦ Агент» и кнопка ✦ видны, только когда настроен провайдер, и
  выключаются в настройках агента.
- Проверка: чистая логика в `td_agent` с тестами, клиент — сборкой и ручным
  чек-листом.

## 12. Риски и открытые вопросы

- Протокол Claude Code может меняться между версиями, а использование
  подписки в стороннем хосте Anthropic может закрыть технически.
- Качество вызова инструментов у локальных моделей. Нужны минимальные
  требования к модели. Возможно, потребуется резервный режим вызова
  инструментов через JSON в тексте для моделей без нативной поддержки.
- Автоматические массовые действия могут привести к ограничениям аккаунта со
  стороны Telegram.
- Провайдеры Anthropic и OpenAI недоступны из части регионов, без
  SOCKS/HTTP-прокси агент там не работает.
- Шифрование ключей на уровне приложения (раздел 10).

## 13. Отложено

- «✦ Агент» как настоящий чат Telegram (сортировка, папки, поиск, пересылка в
  него): слишком глубоко врезается в `dialogs` и историю.
- Pi и ACP как движки.
- Агент, работающий сразу во всех аккаунтах.
- Синхронизация памяти и задач через облако Telegram.
- Голосовой ввод для агента.
